## P1-1 行为变化

### 新增 `omrs/drafts.py`（存储层）

照 `omrs/inbox.py` 的写法：模块级 `_LOCK`、`connect(vault)` 用 `CREATE TABLE IF NOT EXISTS` 建四张表（`images` / `conv_images` / `drafts` / `blocks`，`plan.md` §3.5 schema，`blocks` 另加 `note` 列）、`_log()` 追加 `events.jsonl`。

- 数据落在 `错题/.omrs/drafts/`：`drafts.db`、`images/<sha256>.<ext>`、`events.jsonl`。**不进 Ledger、不收件箱、不写题库。**
- 图片属于对话：`add_image()` 校验 `data:image/(png|jpeg|gif);base64,`、解码后 ≤8MB、用 `inbox.image_size()`（直接复用，不重写）取宽高；同一对话里同 sha 沿用旧编号，新图从 1 连续编号；编号对用户与模型可见（`IMG-n`），模型拿不到 sha 或路径。
- 转述缓存按 `sha256 + 模型名`：`get_transcript()` 在无缓存或模型名不符时返回 `None`。
- `create_draft()` 校验：科目 / 分类非空、知识点 ≤8、至少一个块、至少一个 `section=题目` 的块、文字块必须有文本、图片块引用的 sha 必须已存在、`cause` 非空时 `cause_statement` 必填；任一不过整份不建（抛中文 `ValueError`）。状态由块推导：有图片块 → `cropping`，全文字 → `review`。难度固定 5。
- `list_drafts()` 默认（`status=None`）**只排除 `discarded`**，`done` 照常列出；`limit` 夹到 1–500。
- 事件：`image.add` / `image.transcribe` / `draft.create`。

### `omrs/server.py`（只读路由）

`do_GET` 加 `/api/drafts/` 前缀分派，新增 `_drafts_get`（照 `_inbox_get`）：`list` / `item` / `image` / `counts`。图片路由校验 `sha` 为 64 位十六进制后才读文件，响应带 `Cache-Control: private, max-age=86400`；访问规则与收件箱 GET 一致。新增 `import base64` / `import re`，`from . import drafts as drafts_mod`。

### `tests/check_docs.py`（路由文档工具）

`ROUTE_METHODS` 加 `"_drafts_get": "GET"`——该字典只认列出的处理函数名，不动态发现新方法；不加则 `--write-routes` 抓不到这四条路由、文档同步检查会失败。

## 偏差与说明

- **未新增 `image_bytes()` 辅助函数。** 图片路由直接复用计划里列出的 `image_data_url()` 再 base64 解码成字节，多一次往返但换取函数清单与计划一致（图片上限 8MB，代价可忽略）。
- **`list_drafts` 默认语义。** 计划只说「默认排除只 discarded」，本实现照此：`done` 默认仍列出，已在文档与测试中写明。
- `cause_statement` 与本对话原话的比对（D-P1-5）属于工具层（P1-3），本存储层只校验「`cause` 非空时 `cause_statement` 非空」。
