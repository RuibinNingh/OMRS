# 2026-09-13 架构改造第 3 期：静态资源指纹与缓存

## 变更摘要

- 新建 `omrs/assets.py`：内容指纹（sha256 前 8 位）、HTML 引用改写、ETag 计算。
- `omrs/server.py`：`_serve()` 发 HTML 前先 `stamp_html()`，并给改写后的字节算 ETag，
  响应 `Cache-Control: no-cache` + `ETag`，命中 `If-None-Match` 回 304；
  `_serve_asset()` 按有无 `?h=` 分两条缓存路径。
- `omrs_dashboard.html`：22 个手写 `?v=` 全部删除；Google Fonts 外链换成
  `assets/vendor/fonts/fonts.css`。
- 新增 `assets/vendor/fonts/fonts.css`（占位 + 说明）与 `deploy/fetch_fonts.py`
  （纯标准库，抓 Google 的 css2 定义并把其中引用的 woff2 全部拉到本地再改写路径）。

## 行为与兼容性

- 首屏 1097KB → 二次访问 0KB（HTML 304，26/26 资源命中强缓存）。实测数据。
- 不带 `?h=` 的旧书签、手输地址、导出模板照常工作，只是走 ETag 而非强缓存。
- 字体：不跑 `fetch_fonts.py` 时 `fonts.css` 为空，页面回落到 `styles.css` 本来就有的
  `PingFang SC` / `Microsoft YaHei` / `monospace` 兜底栈——观感变化，布局与功能不受影响。

## 关键决策

- **指纹惰性算、按 `mtime_ns + size` 失效，不是启动时扫一遍**。计划原文写的是启动扫描，
  但那样过不了它自己的验收条款「改一个字节到 `styles.css`，刷新页面新样式立即生效」。
  改成惰性缓存后哈希仍然只算一次，改文件才重算。
- **HTML 也发 ETag**（计划里没有这条）。只发 `no-cache` 的话二次加载还剩 94KB 的 HTML，
  达不到验收要求的「个位数 KB」。`no-cache` 的语义是「每次回源校验」而不是「每次重下」，
  配 ETag 正好，且不影响指纹机制——HTML 内容一变 ETag 就变。
- **带 `?h=` 的响应不发 ETag**：浏览器根本不会来复验，发了是多余字节。
- **woff2 不入库**：Noto Sans SC 被 Google 切成上百个 unicode-range 子集，全量十几 MB，
  提交进 Git 会把仓库体积翻几番。抓一次留在部署机上即可。
