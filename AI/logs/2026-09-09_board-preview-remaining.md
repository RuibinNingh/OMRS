## 2. 第 3 期：交互瘦身与检视能力（未开始）

### 目标

在不破坏现有“纸面 / 列表”主流程的前提下，把右侧设置栏收纳为可发现、可关闭的浮层，并让选中题目时能快速查看和修改纸面几何。

### 任务清单

#### T3-1：第三栏设置浮层化

- 将当前 `#bd-settings` 的长侧栏拆为两个入口：
  - “版面”浮层：右侧留白、题间留白、装订边、缩放/适应宽度；
  - “打印”浮层：答案、题头元数据、切割线样式、切割线标签、打印全部/仅新增。
- 浮层必须支持：打开、关闭、点击外部关闭、Esc 关闭、窄屏不出界。
- 当前控件功能不能减少；只是改变承载方式。
- “切割线三档”必须在这一期获得真实 UI 入口，不能继续要求用户手工 POST API。

**验收：** 浏览器打开展示板，原右栏不再固定占据布局；所有原设置仍能读回并保存；切换板、切换视图、刷新页面后设置不丢。

#### T3-2：选中题检视条

- 点击纸面题目时，宿主页收到 `omrs-board-select` 并记录当前 UID。
- 在纸面舞台上方显示检视条，至少包含：题目序号、UID/题名、当前题后留白、是否已打印、跳转题目详情入口。
- 题间留白支持“行数 ↔ 厘米”双向显示；换算必须使用导出模板同一套几何常量，不能在前端另写另一套比例。
- 对已打印题，明确提示“修改只影响下次打印全部/当前预览，不改历史纸面”。

**验收：** 点击纸面第 N 题，检视条显示同一 UID；修改留白后只保存一次，预览布局变化与导出模板一致；切换页后仍能定位当前题。

#### T3-3：拖动切割线调留白

- 切割线应成为可拖拽的几何控制点或拖拽带；拖动结果换算到 `gap_lines`。
- 设定最小值 0、最大值 48；不能产生负值、NaN 或超过后端上限的 payload。
- 拖动过程中走 iframe `relayout`，不要每个 pointermove 都请求 `/api/export`。
- pointerup 后只产生一次合并保存；失败时恢复拖动前值并显示可理解错误。

**验收：** 连续拖动期间 `/api` 请求为 0；松手后最多一次 `/api/board/update`；刷新页面后留白与拖动结果一致；打印导出中切割线位置与预览一致。

#### T3-4：拆分 `assets/board.js`

建议拆为：

- `board.js`：页面状态、板切换、保存队列、视图协调；
- `board_picker.js`：文件夹树、选板浮层、搜索、最近使用；
- `board_preview.js`：已有的 iframe 预览协议和生命周期继续保留。

拆分要求：

- 不改变全局函数名和 HTML inline handler 的兼容层；
- 先搬纯函数和事件委托，再搬状态；
- 每一步都保留 `node --check`、现有 JS 测试和浏览器主路径验收。

**验收：** 生产页面加载无 `ReferenceError`；选板、加题、排序、保存、预览、打印全部可用；拆分后文件职责清楚且没有循环依赖。

#### T3-5：正文变更后的预览失效入口

当前预览内容签名只覆盖题目集合、顺序、停用/缺失状态和纸面时间，不覆盖题目正文。题目正文被单独编辑后，如果没有触发 `boardReloadData()`，iframe 可能显示旧正文。

本期必须二选一并记录决定：

- 方案 A：题目详情保存成功后主动通知展示板失效；
- 方案 B：检视条增加“重新生成”按钮，明确刷新当前板；
- 推荐：A 为自动正确性保障，B 作为人工兜底。

**验收：** 单独编辑板内题目正文，返回展示板后预览不再保持旧文本；网络请求次数可接受，不得退化为每次几何拖动都重新导出。

## 3. 第 4 期：画廊与统一题目卡片（未开始）

### 目标

将题库画廊的卡片渲染抽成共享组件，使展示板可以在纸面、列表之外提供可扫描的画廊视图，并让选题弹窗也能切换画廊。

### 任务清单

#### T4-1：抽取共享 `qvGalleryCard`

- 从 `questions.js` 当前 `renderQuestionGallery()` 抽取共享卡片函数；建议放入 `qview.js`。
- 共享函数必须接受明确的数据对象，不直接读取题库全局状态。
- 保留现有题库画廊视觉、题目预览、元数据开关、懒加载/水合行为。
- 题库画廊与展示板画廊不得各自复制一份近似模板。

**验收：** 题库画廊回归通过；展示板和选题弹窗使用同一卡片函数；卡片文本、公式、图片和标签无 XSS/转义回归。

#### T4-2：展示板画廊视图

- 启用现有“画廊”分段按钮；不得只是把列表行换成字符串。
- 画廊卡片需要表现：题目序号、题名/正文摘要、科目/分类、难度、标签、已打印/新增/已修改状态。
- 点击卡片要能回到纸面对应题目，或打开检视条/题目详情。
- 当前板为空、含缺失题、含停用题时要有明确空态和状态标记。

**验收：** `纸面 → 列表 → 画廊 → 纸面` 循环不丢选中板、分页、缩放和筛选状态；画廊与板题目数量一致；控制台错误为 0。

#### T4-3：选题对话框画廊切换

- `boardAddPrompt()` 增加列表/画廊切换；
- 画廊中必须保留复选/批量选择能力；
- 搜索、科目/标签筛选和“全部已在板中/部分已有/全新”状态保持一致；
- 切换视图不能清空已选择的题目。

**验收：** 选择若干题后切换画廊再切回列表，选择集合完全一致；提交后板内无重复 UID；已在板题目状态准确。

#### T4-4：版本与文档收尾

- 仅在 T3/T4 的功能、测试、浏览器验收全部通过后，将 `omrs/version.py` 升至 `v1.18.0`。
- 同步模块文档和部署日志；不能提前把版本号写成 v1.18.0。
- 将“第 3/4 期完成、画廊启用、已知限制”写入正式文档。

## 6. 数据与生产验收欠账

### 6.1 真实 boards.json 迁移

当前生产磁盘的 `错题/.omrs/boards.json` 仍显示 `version: 2`，有 4 个板；服务启动后通过内存归一化提供 v3 语义，尚未人为触发一次写回迁移。这是有意的保守行为：本次部署没有直接改题库/运行数据。

后续要在备份后执行一次受控迁移，并核对：

- 每个板的逐题有效留白是否与迁移前相同；
- 已打印板的 `printed` / cursor / segments 是否不变；
- 首次保存后文件变为 v3 且二次保存无 diff；
- `cut_line` 默认值是否符合最终决定。

### 6.2 切割线默认值

当前代码默认 `dash`，服务 API 返回的板也显示 `cut_line: "dash"`。因此历史板在下次打印时会显示淡切割线；第 3 期 UI 完成前，关闭入口只能通过 API：

```http
POST /api/board/update
{"id":"<BOARD_ID>","print":{"cut_line":"none"}}
```

是否保持这个默认值必须由产品决定；若要“老板保持原样、新板默认开”，应在正式迁移逻辑中将 v2→v3 的旧板写成 `none`，并补测试。

### 6.3 真机与触屏

必须用真实打印机至少打印一张包含多题和切割线的 A4，确认：

- 淡线在纸上确实可见；
- 不抢正文对比度；
- 不与题目正文、图片、答案页重叠；
- 打印机不因颜色过浅而完全吃掉线。

还要用触屏设备走一遍：拖动留白、打开设置、切换纸面/列表、画廊禁用态、翻页。
