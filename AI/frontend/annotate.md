# 前端：框选标注页（训练数据采集）

> **速查**
> - 职责：独立页 `/annotate`，批量上传截图、只标「题目 / 答案」两类框，产出检测模型训练数据；脱离题库与收件箱存在
> - 入口：`assets/app/annotate.html`（由 `/annotate` 提供）、`assets/app/features/annotate/`（`index.js` 入口，`store.js` 数据所有者，`state.js` 纯函数，`canvas.js` 画布，`view.js` 模板，`folder.js` 批量入口）；后端 `omrs/annotate.py`
> - 不变量：不写收件箱、Ledger、题目；框只有 question / answer 两种角色、坐标 0–1；导出默认只含「已完成」的图；YOLO 类别号与收件箱导出相同（0=题目，1=答案）
> - 必跑测试：`tests/test_annotate.py`、`tests/app/annotate.test.mjs`、`tests/e2e/annotate.py`
> - 相关：`AI/api.md`（框选标注集端点）、`AI/data.md` §16、`AI/frontend/create.md`（AI 训练页入口）、`AI/inbox.md`（收件箱数据集，格式一致）

## 页面与入口

录入题目页的「AI 训练」工作区有一栏「框选标注页」，显示已上传张数、完成张数与两类框的数量（读 `/api/annotate/stats`，失败时只显示说明）；「打开标注页」是 `target="_blank"` 的链接，在新标签页打开 `/annotate`。标注页不经主页外壳：只加载 tokens、base、ui 样式与本页 `annotate.css`，主题沿用 `theme-boot.js` 读的 `omrs-theme`，远端会话用 `core/activity.js` 续期，401 时由 `core/api` 跳登录页。

布局是顶栏、左栏、画布区三块。顶栏放页名、题目 / 答案角色切换、完成进度（`已完成 / 总数` 与进度条）、导出格式与「导出已完成」链接、快捷键按钮。左栏上半是拖放区、「选择整个文件夹」和全部 / 未完成 / 已完成筛选，下半是图片队列（序号、文件名、题目框数、答案框数，完成的序号前带 ✓）。画布区下方状态行显示文件名、原图尺寸与当前比例、框数、完成状态、保存状态，以及改回未完成、清空框、删除这张、完成下一张四个按钮。窄屏（≤760）改为单栏，左栏在上。

## 上传（批量）

四个入口共用 `store.upload()`：拖放区的选择框、`#an-folder`（`webkitdirectory`）、`Ctrl + V` 粘贴、拖入整页任意位置（文件或整个文件夹）。整页拖放在 `document` 捕获阶段接住，`folder.js` 用 `webkitGetAsEntry` 递归展开文件夹，只收 PNG / JPEG / GIF，其余计数后提示「跳过 N 个非图片文件」；按相对路径自然排序（`shot_2` 在 `shot_10` 前），上传顺序即队列顺序。

上传是一个队列：文件排队后每批 `UPLOAD_CHUNK`（8）张串行发 `POST /api/annotate/upload`，每批回来立即并入列表，所以可以边传边标；传输中继续拖入会追加到同一队列。拖放区标题显示「正在上传 已传 / 总数」并带进度条，队列清空后只弹一条汇总（新增张数、重复跳过张数、失败张数与原因）。服务端按 sha256 去重。

## 画框与编辑

`canvas.js` 把原图、SVG 框层和十字准线叠在 `#an-canvas`（`data-morph="skip"`）里。显示宽度 = 画布区可用宽度 × 缩放，写在 `<img>` 的 `width` / `height` 属性上（不用行内样式），SVG 的 viewBox 用原图像素、线宽不随缩放变，把手与字号按「原图像素 / 屏幕像素」换算成固定屏幕尺寸。题目框用 `--info`、答案框用 `--success`，框内淡填充，标签「题目 1」「答案 1」按同角色出现顺序编号。

空白处拖动画当前角色的框，按住 Shift 画另一种；小于 6 屏幕像素的新框视为误点丢弃。拖框移动，拖选中框的八个把手缩放。拖到滚动区边缘 40 像素内开始自动滚动，越往外越快（`edgeSpeed`，每帧最快约 90 像素），长截图可以一口气从题目顶部拖到答案底部。`Ctrl / ⌘ + 滚轮` 缩放，缩放档位跨图片保持。

刚画完的框处于选中（可以马上拖把手），但此时按 Q / A 只切换下一个框的角色；点选或 Tab 选中的框按 Q / A 才改它自己的角色（`state.picked`）。「沿用上一张」取本次最近完成的有框图片（没有就取最后一张已完成且有框的），横向照搬，上部（y<0.35）的框按像素锚定顶部、其余按比例，与收件箱的沿用规则一致。

## 保存与完成

`store.js` 是唯一数据所有者，I/O 注入。任何框位改动先记撤销快照（每张图一条栈，最多 100 步），整体替换后去抖 400ms 调 `POST /api/annotate/save`，携带当前 `expected_revision`；同一时刻只有一个请求在途，期间的改动排到下一轮。保存成功接收新 revision；失败则保留本地框与待存队列、停止继续写该图并提示核对后刷新。后台重读不覆盖待存、在途或失败的本地框。删除先写完待存改动，再携带 revision；冲突时保留当前图。切图、`Ctrl + S`、页面隐藏时立即写出；有未写出的改动时离开页面会弹浏览器确认。

`Enter` 把当前图标为完成（随保存带 `status: "done"`）并跳到其后第一张未完成（绕回开头）；没有框时拦住并提示，确实没有题目用 `Shift + Enter` 标为空白样本（YOLO 导出为空标签文件）。全部完成时提示并停在当前图。「改回未完成」把状态写回 `todo`。删除当前图（按钮或 `Shift + Delete`）先确认，删除后停在同一筛选里的相邻一张。

## 快捷键

登记在 `core/keys` 的 `annotate` 作用域，输入框里与对话框打开时不触发；`?` 打开完整表（`view.js` 的 `SHORTCUTS`）。`Q` / `1` 题目，`A` / `2` 答案，`Tab` / `Shift + Tab` 切换选中框，`Delete` / `Backspace` 删框，`Ctrl + Z` 撤销、`Ctrl + Shift + Z` / `Ctrl + Y` 重做，`C` 沿用上一张，`F` 整张图一个框，`Esc` 取消拖动或选中，`Enter` / `Shift + Enter` 完成，`←` / `→` 翻页，`+` / `-` / `0` 缩放与适应宽度，`Ctrl + S` 立即保存，`Shift + Delete` 删除这张图。

## 大批量下的渲染

队列按行增量更新：可见图片的 id 序列不变时只对签名（序号、是否当前、状态、两类框数、文件名）变了的行做 morph，序列变了才整表 morph；序号表一次算好。顶栏、左栏上半、状态行在模板文本不变时跳过 morph。拖动中只重画画布的框层。切图时预加载前后各一张原图。实测 3000 张时首屏约 1–2 秒、翻页每次约 20ms（受限模式单核沙箱）。

## 样式

全部在 `features/annotate/annotate.css`，类名前缀 `an-`，只用 token。本页键帽放大到 `--text-xs`（全站最小字号 12px）。十字准线只在指针位于画布上时显示。
