# 前端：AI 助手页

> **速查**
> - 职责：`#/assistant` 页面——对话列表、附图消息、运行轨迹、草稿卡片、确认与撤销、检查器、上下文用量
> - 入口：`assets/app/features/assistant/index.js`（页面契约与控制器）、`attachments.js`（图片校验与缩放）、`interactions.js`（输入和拖放）、`mobile-layout.js`（可见视口）、`state.js`（事件归约）、`view.js` / `insp-view.js` / `tools-view.js`（视图）
> - 不变量：模板不写 `style=`，条形、瀑布、火花线、用量环一律 SVG 属性；已结束的运行带 `data-hash` 整棵跳过 morph；批准只由用户点按钮发出，绑定已展示的提案版本
> - 必跑测试：`tests/app/assistant.test.mjs`、`tests/e2e/assistant.py`、`tests/e2e/assistant_p3.py`、`tests/e2e/assistant_race.py`、`tests/e2e/assistant_review.py`
> - 相关：`AI/agent.md`（接口、事件、权限）、`AI/frontend/settings.md`（AI 助手分区）、`AI/frontend/design-system.md`

## 结构

三栏网格：左栏对话列表（按上海业务日期的今天 / 昨天 / 更早分组，非法时间归到更早，运行中与等确认有活动点，写过数据的标「写入 N」）、中栏对话（头部、滚动区、底部输入区）、右栏检查器（默认收起，头部按钮或运行页脚的图表按钮打开）。≤1160px 时左右两栏变抽屉，共用一层遮罩；≤760px 时建议芯片改横向滚动。侧栏入口 `.tab[data-tab="assistant"]` 在 `agent_enabled` 为假时隐藏，运行中高亮图标、等确认时变警示色；`main.js` 启动后调 `syncAssistantNav`，设置页保存后经总线事件 `agent:config` 再同步一次。

## 状态与渲染

`history.js` 负责对话列表、成组历史和运行事件的有界读取；`references.js` 负责引用芯片与侧栏状态，按上海业务日期判断到期。控制器状态 `S`：状态接口结果、对话列表、当前对话条目（用户消息与运行）、展开 / 收起的步骤、选中的运行、浮层与抽屉开关、是否贴底跟随。按区域 morph（左栏、头部、对话流、输入区、检查器），requestAnimationFrame 合帧；有运行进行时每 250ms 重绘一次刷新计时。打开对话时递增请求序号，迟到的旧详情不覆盖当前选择；页面卸载使在途详情失效。旧运行结束只清理属于同一对话、同一运行的活动态，不清掉刚打开的新运行。已结束运行的 `data-hash` 由运行 id、事件版本、界面版本组成，展开步骤或撤销后版本变化才重画。贴底跟随只在用户自己滚动（滚轮、触摸、键盘）离开底部时停止，出现「回到最新」。

`state.js` 把事件归约成运行视图模型：步骤（转述图片、思考、正文、工具、插话）、时间线段（模型轮次的等首 token / 生成、工具的等确认 / 执行）、用量、首 token、速度窗口、写入列表。`image.transcribe` 与 `image.transcribed` 在首轮模型请求之前生成「转述 IMG-n」步骤，显示进行中、完成或失败与耗时。持久化时合并过的增量与逐片增量归约结果一致（有单测）。

聊天正文按 Markdown 段落渲染；工具结果卡里的题目摘要、题面差异和草稿预览使用同一套内联转义，并把普通换行输出为 `<br>`，避免 AI 逐行文本在这些辅助卡片里合并。

`usage.js` 按稳定请求标识归约用量，同一请求结束值替换流式估算，重复事件和刷新重放不重复累计；明确 `completion=0` 会覆盖估算。输入区圆环旁同时展示上下文占用与缓存命中；点击用量入口可在同一弹层查看上下文构成和缓存统计。运行详情把输入（未缓存部分）、输出、缓存列为互斥三项，本次总量按三项相加；未知缓存保持未知。缺缓存字段显示未知或部分覆盖，新事件的显式零显示 0%；旧事件只有 `cached=0` 时无法区分缺失与明确零，按未知处理。检查器分别列主对话、图片辅助和已知总量；请求缺最终用量或中断时不宣称完整总量，缓存、思考作为输入或输出的子集展示。

## 交互

发送：桌面 Enter 发送、Shift+Enter 换行；手机 Enter 换行、点发送按钮提交；输入法组合中及结束后的短时间内 Enter 不发送。运行中再发纯文字即插话（虚线框提示，下一轮前送达）。聊天主面板和输入区都接受文件拖放，统一遮罩只响应文件类型；粘贴与回形针按钮也可加 PNG / JPEG / GIF，PDF/TXT 明确提示不支持。最多 6 张，每张最多 8MB，长边超过 4096 的图经 canvas 等比缩成 JPEG 0.9；JPEG 清除主图后的相册数据，缺尾时补标记。处理中的图片计入数量限制并禁用发送；切换会话、清空附件、离开页面会使迟到读取失效，切换成功时再次清空切换期间拖入的图片。有图时请求增加 `images`，大图通过 `core/uploads.js` 分块后传 `{upload_ref}`，小图保留内联兼容，纯文字仍只发 `conversation_id` 与 `text`。发送失败保留文字和图片；转述模型未配置时发送前提示。待发送图与历史 `IMG-n` 图片都走 `ui/image-viewer` 站内预览；历史图从 `/api/drafts/image?sha=…` 读取，不重新上传。

手机聊天模式隐藏外壳重复顶栏，由助手头部一行保留主导航、对话列表、标题、新对话与运行详情。消息区独立滚动，输入区按 VisualViewport 的可见高度落在软键盘上方；页面缩放时不作键盘补偿。空输入一行，通常最多增长至四行并内部滚动；输入区不提供独立的展开 / 收起按钮，附件横向滚动，用量入口同时展示上下文占用与缓存命中。快捷建议只在空对话、未输入且未聚焦时出现。长用户消息默认折叠，可展开全文，DOM 中仍保留原文供复制；每次运行以「处理中」总字段显示过程，过程默认展开；完成后仍保持展开，用户点击右侧折叠图标才收起。最终回答、待确认操作和写入卡始终直接展示。浏览器返回键关闭图片预览，Esc 与关闭按钮也可关闭并把焦点还给触发元素。

`create_draft` 工具完成后自动展开结果卡片，显示草稿编号、科目 / 分类、题目前 60 字、文字或图片块类型及「待审核 / 待框选」状态；卡片有「查看草稿」，通过 domain/ai-review 的面板端口在聊天原位打开完整草稿详情。卡片用当前草稿详情叠加历史结果，响应变更与窗口聚焦刷新，变更时使已结束运行的 data-hash 失效；读取失败保留重试入口。草稿不进 Ledger，所以不在按运行撤销列表中。停止：`/api/agent/abort`。需要批准的工具卡片读取 `/api/ai-review/detail` 叠加当前状态与有效期。标记、知识点、反馈、移动、停用 / 恢复、分类与复习计划等轻量操作直接展示影响范围并提供确认、拒绝和完整预览；确认按钮携带已展示的 revision，重新读取发现提案变化时必须重新核对。重复点击合并为一次决定，读取失败保留已核实内容并禁止决定，提供重试。

操作卡只展示当前服务端状态；已确认待执行与实际完成分开。成功默认收起逐项变更，失败、冲突、过期和部分完成默认展开。标记卡依据实际 changed / skipped 回执解释修改数量，不把无需变更题目算作失败。完整预览、人工修订和草稿编辑复用审核中心控制器，桌面侧抽屉、手机全屏，不改聊天路由。关闭保留输入、消息位置并恢复入口焦点；关闭按钮、Esc、遮罩与离页均保护未保存输入，执行中禁止关闭。聊天草稿详情只处理当前草稿，入库或丢弃后保留当前回执，不自动打开无关草稿。

撤销：运行页脚「撤销这次写入」先取 dry-run 计划，有冲突时对话框只列冲突。引用芯片：正文与预览里的题目 UID 变成按钮（圆点按到期 / 顽固 / 停用着色），点开走 `domain/question` 的题目弹窗；Session 号跳复习调度。运行结束且有 Ledger 写入时刷新题目数据、Session 与题目缓存并提示。

`create_category` 的确认卡明确科目、分类及永久写入边界，执行结果卡显示新建或已存在。`update_draft` 的结果卡默认展开，显示已保存的 revision 或人工保护建议，并可在原位详情审核；当前草稿版本更高时提示先核对。助手将成功修订发为 `drafts:changed`，草稿审核页若有本地脏输入则保留并提示冲突。

人工保护建议的目标、当前内容与 AI 建议直接显示在卡片中，工具结果随对话运行持久化，可刷新后重看。草稿和分类写入即使没有 Ledger commit 也计入运行写入数与检查器活动；无 commit 时不出现按运行撤销按钮，检查器说明该项不能自动撤销。

`create_practice_card` 的结构化工具结果在聊天中显示标题、题数和「开始练习」入口。入口把卡片 ID 放进 `#/instant?practice=`，由即时练习页读取服务端题序；展示摘要不作为数据源。再次点卡片入口续最近 attempt；删除对话后不能再开始新轮次，已签发的练习和真实反馈仍保留。

## 样式与 token

三份样式：`assistant.css`（布局、列表、头部、消息缩略图、空状态与权限表、入口状态、断点）、`assistant-run.css`（轨迹、转述步骤、工具行、确认卡、正文 Markdown、引用芯片、页脚）、`assistant-side.css`（输入区附件条、用量浮层、检查器、工具预览、对话框内容）。派生色与字号放 `tokens.css` 的「助手页」段（`--ast-*`）；页面级尺寸（栏宽、引用内边距）是 `.ast` 上的局部自定义属性。输入框高度用 `field-sizing: content`，不写脚本改高度。

处理区的状态入口是轻量的可折叠状态行，显示处理中 / 处理完成及耗时；工具步骤才使用带边框的工具卡片，避免两种层级混在一起。状态行仍保留键盘焦点、悬停和完成后的展开 / 收起能力。

确认模式下注册 commit_draft，确认卡展示该 revision 的元数据、错因、文字与图片预览；只有明确确认才入库。工具成功后发 drafts:changed 刷新卡片及角标；等待期间内容变化会在服务端拒绝旧许可。

草稿框选方式为 ask 时，待框选卡片显示「AI 框」和「我来框」，前者登记检测作业，后者复用草稿导航入口；manual 只显示「查看草稿」，auto 的新草稿自动排检测任务。卡片叠加当前后台任务状态，完成后刷新；共享图和人工框仍由后端保护。配置在重进页面、聚焦和 agent:config 通知时重新读取，卡片样式随当前模式更新。

## 有界历史读取

对话列表默认每页 30 条，提供「更多对话」；详情按每页 20 个运行组加载最新页，提供「加载更早的消息」，向前插入后保持当前滚动位置。运行轨迹初页最多 200 条事件，有后续时明确标记未全部读取并提供「继续读取运行记录」。活动运行继续按稳定事件序号长轮询；完成／重启后的序号和历史游标由服务端持久化，历史仍可逐页访问。

用户消息与运行使用持久 `item_key`，加载更早页不改变展开状态、图片定位或当前运行对象。分段读取未到结束事件时不合成提前终止，后续 delta 可正确续接。对话切换与卸载丢弃旧页响应；当前运行结束后刷新对应领域和最新列表。

## 审核中心状态同步

`review-cards.js` 用 waiting 事件或结果中的 operation_id 定位公共操作，叠加服务端状态与提案版本，不改写历史事件。聚焦、加载对话与事件、中心变更通知触发刷新；活动审批每 2.5 秒轮询，隐藏或卸载停止。`reviewVer` 使已结束运行的 data-hash 失效，避免返回聊天后看到旧批准按钮。旧无操作编号的确认轨迹只读，入口跳审核中心，失效 token 不再由前端批准。

正式复习计划和标记修改也进入人工审核；自动草稿、草稿修订与聊天练习卡留下业务写记录。按运行撤销继续使用原 Ledger 契约，审批记录与原执行回执分别保存。完整入库草稿预览、有限正式题目修订与共同决定行为见 `AI/frontend/ai-review.md`。
