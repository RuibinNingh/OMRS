# 前端：录入题目与收件箱工作台

> **速查**
> - 职责：录入页五个工作区（上传、处理、录入、AI 训练、快速录入）与 AI 草稿跳转入口的界面、收件箱前端数据与保存队列；后端流程见 `AI/inbox.md`
> - 入口：`assets/app/features/create/`（`index.js` 页面契约，`inbox.js` / `inbox-store.js` 收件箱数据，其余按工作区分文件）
> - 不变量：原图先入收件箱暂存层，提交后才写题库；切页保留工作区、当前图、勾选与快速录入草稿；离开处理区或本页前写出未到防抖时间的改动；创建后保留上下文字段
> - 必跑测试：`tests/app/create.test.mjs`、`tests/app/create-process.test.mjs`、`tests/app/create-inbox.test.mjs`、`tests/e2e/create.py`、`tests/e2e/drafts_blocks.py`、`tests/test_inbox.py`、`tests/test_ai_assist_taxonomy.py`
> - 相关：`AI/inbox.md`、`AI/frontend/architecture.md`、`AI/frontend/design-system.md`

## 页面与工作区

`#panel-create` 在 HTML 里只有导航 `#create-flow` 和工作区容器，内容全部由 `features/create/index.js` 挂载。导航由 `state.js` / `view.js` 渲染六个按钮（`data-action="create.stage"`），前三项按流程编号并显示待处理、已框选、待创建三个计数。当前工作区存在收件箱单例的 `stage` 里，切到其它页面后返回仍停在原处；进入 AI 训练时重读统计与策略。

录入页的快捷键登记在页面契约的 `keys` 里，只在处理区生效：`Q` / `A` / `X` 切画框角色、`Delete` / `Backspace` 删除选中框、`Enter` 下一张、`⌘/Ctrl + Enter` 一键提取、`Esc` 取消选中框。

## 收件箱数据（`inbox-store.js` / `inbox.js`）

`createInboxStore({ api, emit, notify, timers })` 是收件箱在前端的唯一所有者，I/O 全部注入，node 测试直接构造；`inbox.js` 用 `core/api` 与 `ui/toast` 建模块级单例，挂载时 `connectInbox(bus)` 接上通知通道。状态包括图片列表、网格与处理区共用的勾选、当前图、选中框、画框角色与题卡和题卡勾选。任何改动都发 `inbox:changed`，各工作区控制器按需重绘。

保存队列按字段冻结补丁，同一张图的补丁在防抖期内合并（`cards` 按题卡合并），请求按服务端 `revision` 串行，始终携带 `expected_revision` 与 `reset_epoch`。收到 409 时只在所写字段未被其他操作改动时重读并重试；同字段冲突或请求失败会保留本地编辑、阻止该图后续写入并提示核对。`load()` 不覆盖待保存、在途、冲突或正在拖动的对象；读取失败也保留当前列表。`flush()` 在离开处理区、离开本页和创建题目之前调用，返回失败时不继续录入。后台任务 `job(type, payload, onDone, onError?)` 每 1.2 秒轮询一次，同一任务不会并发轮询；失败项与轮询错误都经提示报告。

`inbox-ops.js` 放网格、处理区和题卡共用的操作：AI 框选（按 `slice-plan` 切条带）、整图即题目、文本提取、题卡分类识别。`crop.js` 从共享 `domain/image-crop/` 导出浏览器裁图能力，超过约 150 万像素的 PNG 改 JPEG 0.9 白底；预览 canvas 带 `data-crop="图片|区域"`，按框位键只在框变化时重画。

## 上传与收件箱网格

`upload.js` / `upload-view.js` 用 `ui/filedrop` 接受多张图片的选择与拖放；上传工作区也能粘贴图片或显式读取剪贴板，四种入口共用 `core/uploads.js`：原图以 16MiB 分块暂存，再提交 `/api/inbox/upload-refs`。非图片、剪贴板不可用和请求失败在控件旁提示；请求期间禁用入口。上传成功发 `inbox:reload`，页面重读收件箱，重复图片由接口合并。

`grid.js` / `grid-view.js` 渲染原图卡片和框位预览，提供全部、待处理、已框选、待创建、已录入五种筛选。全选只选当前筛选里未录入的图片；批量条只处理已选图片，包含 AI 框选、整图即题目、去处理、丢弃和清空选择。已录入卡片打开关联题目；批量丢弃失败时保留选择并在网格旁提示。

## 处理（框选）

`process-view.js` 挂三栏骨架：队列、画布、区域面板。`process.js` 负责本张图的全部编辑：切图、角色、整图、清空框、重置此图、新题卡、删除框、提取结果审核、文本编辑、一键提取、丢弃与标记就绪。「重置此图」经确认后清空当前截图全部处理进度并保留原图，提取卡住时仍可使用；旧保存和后台结果不会恢复已清空的内容。队列行与区域卡片由 `process-content.js` 渲染，事件都是 `data-action` / `data-change` / `data-input`；点在复选框、输入框上时不触发整行动作。

画布在 `data-morph="skip"` 的 `#ib-stage-img` 里，原图与 SVG 框位由 `process-canvas.js` 直接渲染，指针手势（画框、移动、八向缩放）只由它处理，坐标为 0–1（纯函数在 `process-state.js`）。拖动时不重绘面板，松手后状态随框数更新并去抖保存。保留图片的区域在面板里显示裁图预览（外层 skip，键含框位）。点击「一键提取」只处理当前图未完成或过期、失败的非忽略区域，每个区域一次请求同时判断和转录；不会覆盖已经审核选择的区域。提取前没有保存方式选择，结果出现后以弱按钮提供「保存为图片 / 改用文本」及「重新提取」，切换保留已有文字，无文字时可人工补录。

提取期间禁止重复提交和修改本图框位，可切到其它图继续；完成后重读收件箱并保护本地未存改动。轮询失败、单区域失败和明确不可提取分别处理，失败可重试。框位或角色变化使旧结果失效，必须重新提取。标记就绪前先排空保存队列；失败时停留当前图并保留编辑。就绪要求各非忽略区域已有有效判断，文本区有正文；仍须用户审核后主动点击，自动策略也不会跳过这一步。保存成功后切到下一张未就绪的图，并在「区域与转换」标题下的局部状态块显示成功反馈，数秒后自动隐藏；错误和警告仍使用全局 toast。

收件箱和快速录入的文字提取遵循「设置 → AI 识别」的思考开关；当前仅对 `deepseek-flash` 显式启用或关闭思考，其它模型沿用服务商默认行为。区域仍逐个处理，前端照常轮询任务状态。

## 录入（题卡）

`cards-state.js` 从就绪图片按题卡分组，已创建的题卡跳过，缺表单时就地补默认表单。`cards-view.js` 每张题卡一行：左边是题目 / 答案预览（转文本的区域复用 `domain/question/markdown.js`，默认保留普通换行、空行按 Markdown 分段，并带 `data-hash`；保留图片的区域画裁图），右边是科目、分类、难度、知识点、标记和错因。科目、分类、知识点使用共享可搜索建议框，分类候选按当前科目过滤。`cards.js` 把字段去抖 600ms 写进收件箱的 `cards`，写入路径随科目分类即时更新；人工修改写入 `manual_fields`，识别时不会覆盖。

标记经 `domain/labels` 的录入选择器改。「AI 识别题目信息」用题卡第一个题目区域提交 classify 任务，完成后重读收件箱，服务端核对任务代次与版本，只填仍空缺的项。「退回处理」把图片改回已框选并打开处理区。创建前先预检科目、分类，再确认 `flush()` 成功；失败不录入。随后取当前图片的 revision/epoch，裁出保留图片的区域，随 `/api/inbox/commit` 提交，大裁图自动分块后传引用。单卡与批量互斥，异步裁图后再次核对代次与 revision；已创建题卡重试复用原回执，不再次创建。单张成功弹一条带「加入展示板」的提示；批量逐张提交，最后只弹一条汇总，「加入展示板（N 题）」一次加入这批新题。成功后刷新统计、历史和目录。

## AI 草稿入口

「AI 草稿」保留为兼容入口，先写出录入页待保存内容，再进入 `#/ai-review?type=draft`。草稿编辑与来源对照由审核中心完整拥有，见 `AI/frontend/ai-review.md`；录入页不持有草稿表单、画布或离页守卫。已有 sessionStorage 目标和跨页草稿链接仍由 `domain/drafts.js` 交接。

## AI 训练

`train.js` 在进入工作区时读 `/api/inbox/dataset/stats`、`/api/config` 与 `/api/annotate/stats`。指标卡下面是「框选标注页」一栏：显示独立标注集的张数、完成数与两类框数，「打开标注页」在新标签页打开 `/annotate`（见 `AI/frontend/annotate.md`）。`train-state.js` 把统计换成展示模型：四张指标卡（`ui/stat`）、版式与转换决策条（原生 `<progress>`）、盲标评估集与存储文案。导出是一个随格式变化的下载链接（OMRS JSONL / YOLO）。清理超期丢弃图直接执行；清空裁图缓存先确认。统计或策略读取失败时在原位显示原因和「重试」。

「框选提供方与自动策略」表单用 `ui/field`、`ui/select`、`ui/switch`：只提供多模态模型与本地检测服务；选 `local_http` 时才显示本地检测地址。保存时把阈值夹到合法范围，写 `/api/config` 的 `inbox_*` 键，结果就地显示。「自动提取的置信度阈值」沿用 inbox_auto_ready_conf 配置名，达标只自动提取，仍待人工审核。

## 快速录入

`quick.js` 持有快速录入草稿、图片和当前粘贴目标；`quick-view.js` 渲染截图工作区与题卡内容双栏，窄屏改为单栏。宽屏题图和答案图区并排，答案区起初是紧凑折叠入口，添加或粘贴答案图片后展开。上传区由 `ui/filedrop` 自身居中；空缩略图和空状态不占位置。题目和答案各有独立的上传、缩略图、移除按钮和显式读取剪贴板按钮。点击或聚焦图片区切换粘贴目标，默认题目区；只有当前页的快速录入工作区会捕获图片粘贴，文本粘贴保持浏览器原行为。

题目图片区读取第一张题目图：`/api/ai-recognize` 的 `classify` 模式补科目、分类、难度与知识点；`question_text` 模式把题面填入文本框。答案图片区的 `answer` 模式读取第一张答案图，把解析填入答案框。quick 请求传 `scope:"quick"`，模型、服务端白名单和前端合并三层都不允许 AI 写标记。识别绑定当前题目对象、题图与答案图 ID、请求时字段快照；更换图片、重置或创建下一题后丢弃旧结果，识别期间改过的字段不覆盖。默认难度 5 与人工改过的 5 用 `manual` 区分。带文字引用的错因只展示为候选，人工核对原图后可点击采纳。识别失败、响应模式错误和空文本都在对应图片区显示原因。

保存调用 `/api/create`，发送科目、分类、难度、知识点、人工标记、题面、答案、错因，以及分开的 `question_images` 和 `answer_images`；不发送笔记本页码。科目和分类由前端预检。成功后只清空题面、答案、错因和两区图片，其余字段保留，方便连续录入。成功提示含 UID、文件路径、图片数和「加入展示板」入口（`domain/board` 的 `boardQuickAdd`，Shift + 点击直接加进上次用的板）；同时刷新统计、历史和目录。按「重置」才清空整份草稿。

快速录入底部的「创建题目」在 760px 以下屏宽保持至少 44px 高；360px 触摸浏览器 E2E 同时核对实际按钮尺寸和页面横向溢出。

快速录入和收件箱题卡的科目/分类建议合并 `/api/taxonomy` 的零题分类与已入库题目；分类候选仍按当前科目过滤。读取失败保留已有题目的候选，重新进入页面会重读词表。

## 样式

样式都在 features 层：`create.css`（导航、工作区显隐与整屏工作台、上传、快速录入、网格）、`process.css`（处理区，作用域 `#ib-stage-process`）、`cards.css`（`crc-`）、`train.css`（`crt-`）与 `drafts.css`（草稿队列、连续正文、统一底部操作与来源模式）。只用 token；标注色取 `--info` / `--success` / `--danger`。旧 `styles.css` 里已没有录入页的规则。

处理区的文字框与输入框用 `ui-textarea` / `ui-input`（与全站同一套控件）。

AI 训练工作区在原标注入口旁显示「训练面板」：实际在线模型、服务离线状态与训练目录当前模型分开标注，运行中另有轮次摘要；只有在线模型可关联评估时才展示对应数据集的答案框 IoU，读取失败显示说明。「打开训练面板」在新标签页打开 `/train`。原统计、导出、清理、提供方与标注入口保持原行为，独立页见 `AI/frontend/trainpanel.md`。

训练面板入口摘要中的旧框指标明确标为IoU达标率，不能用作内容验收；内容判定与人工复核在独立面板的评测记录查看。

## 附件上传

`core/uploads.js` 保留原始文件字节、MIME 与名称，通过 start／chunk／complete 返回暂存 `upload_ref`；单块最多 16MiB，瞬时失败重发同一块，失败不进入后续创建。快速录入原图先暂存，再用于识别或创建；收件箱条带、区域裁图、题卡与草稿的大图自动改用引用，小图内联兼容。原图上传不通过 canvas 缩放；裁图按既有裁剪参数生成，其画质规则不因传输改变。

保存配置返回 `mirror_pending` 时显示「配置已生效，配置镜像待同步」，不把已发布修改说成失败。

草稿转文字与入库准备的裁图同样复用 `imageValue(..., "draft")`，大裁图按原字节分块后只传引用，上传失败保留当前草稿。草稿浏览器回归在保存确认显示「已保存」后核对领域结果，避免把在途请求当成已完成。
