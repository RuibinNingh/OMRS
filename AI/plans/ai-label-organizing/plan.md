# MCP 与助手标记整理

执行者：Codex，完整模式。用户已批准本计划并要求执行到完整功能、验证、文档与本地提交全部完成；不包含推送、部署或生产变更。

## 1. 目标与原话

> 我想让他们能创建合并删除标签等等
> 旨在帮助我归类题目

两者共用创建、编辑、合并、删除与逐题归类能力。分批分析几百道题，整份方案一次批准；支持人工修订、检查真实结果和整批撤销。内置助手在原对话确认，MCP 在网页审核中心确认。跨科目变更单列、默认关闭，由用户勾选后纳入同一次最终确认。

## 2. 背景与规范

开工按根 AGENTS.md 与 AI/README.md 任务索引读标记、助手、MCP、审核、Ledger、存储、安全、备份及相关前端文档。以工作区代码为准，保护已有改动。现有定义保存在 labels.json，题目 YAML 保存名称；原级联逐题写入且部分异常会被跳过。现有审批库、十分钟票据与原生回执复用。助手的调用预算与结果截断必须适配批量归类。

另一聊天“优化 AI 助手审核流程”完成后的提交为前端接入基线。准备中的业务方案不得依赖另一聊天未交付的改动。

## 3. 最终行为

创建优先复用已有标记；同批新定义可用于打标。编辑名称、颜色、排序，改名级联全部引用。合并保留目标定义、迁移去重并删除源；删除定义并摘除引用。逐题支持不同添加、移除方案和理由，保留其它标记。方法、题型依据内容判断；错因标签依据已有错因或用户原话；不充分的图片题与不确定题列为待判断。新建加成固定零，已有加成保持。

对话卡展示范围、进度、数量和状态；完整方案在同页抽屉展开。跨范围改名、合并、删除默认关闭，明确科目、题数和逐题影响。修订后重算预览、递增版本和换票据，不延长原期限。

## 4. 阶段与提交

0 建立基线与计划；1 共享领域、journal、撤销及旧网页可靠写入；2 准备与统一审批；3 MCP/助手工具、权限与设置；4 共用前端预览、修订、结果、撤销；5 故障注入、SDK、真实浏览器、视觉和全门禁。每阶段独立提交代码、测试、文档、同一日志和进度；阶段检查点不是终点。

## 5. 接口与技术决定

共用工具 list_labels、get_labeling_candidates、stage_label_plan、propose_label_plan；单项操作也是一份方案。候选返回稳定 question_id、正文哈希、摘要、截断标志与游标，每页最多二十题、序列化不超过 22000 字符，该工具结果上限 24000，其它维持 6000。准备分片最多五十显式题、整批最多一百定义操作和一千实际受影响题；级联完整计算，不能截断执行。

新增 prepare 工具级别，只组装技术草稿，计调用不计业务写预算、不生成待审项。草稿存于进程内受限存储，绑定 Vault 世代和助手对话/MCP Key，闲置三十分钟或重启失效。正式提案完整落审批库，不依赖草稿。分片同编号同内容幂等，不同内容冲突，旧版本不得覆盖。预算不足保留准备进度，明确未分析范围，下次同对话继续。

已有标记用稳定 ID，新标记用方案内引用并在正式提案预分配 ID。服务端编译每题最终集合、每文件只写一次；自环、循环、重复冲突、名称冲突、非法引用整体拒绝。改名/合并/删除收集全部未归档引用（含停用）；归档与历史不改。定义摘要、题目身份/哈希、级联集合绑定批准。

人工可改原新建/编辑的名称、颜色、排序，排除原操作/题目，调整原题在允许集合的加减，勾选原跨范围操作；不得增加目标或类型。取消创建同时取消依赖，预览明确。MCP 新 scope label:write 与 label:delete 默认关闭，准备/提交需 omrs:read+label:write，合并/删除额外需 label:delete；发现、调用和实际执行都检查实时权限。旧 Key 不自动增权，模型无批准接口。

## 6. 写入、边界与撤销

按生命周期租约→全局写锁→存储锁顺序。复核批准、期限、来源、世代与全部快照，暂存所有文件和定义，持久 journal，文件替换与逐题元数据事实、批次审计、原生回执在同一 Ledger 事务完成，提交后发布投影和清理。相关读取一致性保护。提交前失败回滚本批文件；提交后响应/审批失败由回执补记，不重放、不回滚。恢复材料或身份不符保留现场并阻止写入；旧世代不改恢复后的 Vault。接入启动、扫描前和备份恢复；GET 只读。

新增 GET /api/label-plan/revert-preview 与 POST /api/label-plan/revert，用户从聊天结果或审核记录主动预览、确认。检查相关定义、题目和新增引用，冲突整批拒绝，保留不相关后续修改。逆操作使用同一 journal，另记撤销事实不改历史。助手按运行撤销识别完整批次，不得只撤元数据而遗漏定义。

## 7. 范围

共享标记服务、恢复、审批、助手运行时和工具、MCP 权限及说明、设置控件、聊天与审核详情。旧网页 API 保持请求/响应，复用可靠层；labels.json 和 YAML 格式保持。不加层级、定时整理、目录迁移、知识点重构、调参或换模型。

## 8. 验收

两者完整混合方案；三百道合成题分批组装一次确认；批准前无业务变化；同批创建可打标；助手不改聊天路由；跨科目默认关且勾选后更新版本；正确级联合并/删除；重试、竞争、过期、拒绝、中止、吊销不重复/越权；每个故障阶段可回滚或有真实回执；整批撤销与后续冲突；筛选、统计、读取、扫描、投影一致；熟练度、反馈、状态、加成和正文保持。

## 9. 验证

新增领域、助手与 MCP 单测和隔离 E2E（临时 Vault、随机高端口、假模型、真实 SDK/Chromium），覆盖审批修订、跨科目、幂等、断点恢复及撤销；浅深、手机 390px 与桌面、聊天位置和未保存输入。新增 E2E 入 tests/e2e 自动发现。收尾生成 routes/log index，运行 tests/run_gates.py 的 unit,ui,e2e,release,visual,docs 组，--ref 为阶段0实际基线。清除 OMRS_SYSTEMD_SERVICE 与 OMRS_BOXDETECT_CONTROL。视觉逐项解释；没跑的付费模型、实体手机、公网与真实检测数据单列，不充通过数。

## 10. 执行原则

连续执行全部阶段，只在目标/范围矛盾、无法判断改动归属、真实数据无法可靠恢复，或需未授权外部变更时停下。中断留工作区、更新 progress 状态与未跑验证，恢复先读 status/log/状态块。按 AGENTS 文档映射同步，最终中文报告提交、实跑验证、未跑项、遗留和下一步。
