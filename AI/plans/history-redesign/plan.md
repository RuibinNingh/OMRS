# 历史记录页与 MCP 运行记录

执行者：Codex，完整模式。采用用户已确认的「分区时间线」草稿，单个完整切片提交代码、测试、文档、日志及进度。

## 1. 任务目标

保留历史记录入口，分为「学习与变更」「系统运行」，首批系统记录覆盖 MCP 工具调用。用户原话：「我打算给OMRS历史记录页重设计一下」「还要加上系统运行记录」「比如MCP」「给我草稿」「差不多」「执行修改」。用户已选择先做方案、首批只覆盖 MCP，并认可分区时间线草稿。

## 2. 当前背景与约束

代码复核：历史页读取 Ledger 分页摘要与按需详情，支持反馈和 Session 修正；MCP 当前没有逐次调用的持久化记录。人工草稿入库的 Ledger 载荷已含 `_draft.draft_id`，可复用关联，不伪造旧调用。遵循根目录 `AGENTS.md`、`AI/frontend/records.md`、`AI/frontend/design-system.md`、`AI/mcp.md` 与 `AI/security.md`。

## 3. 最终预期行为

- 学习记录按天分组，默认最新在前，保留用户已有排序偏好；选择节点查看详情，显式修正模式保留既有全部操作。
- MCP 记录显示动作、密钥名称、时间、状态、耗时；支持时间、搜索、密钥和状态筛选、分页与按需详情。
- 系统记录持久化成功、失败和进行中状态；服务重启后遗留进行中记录标为中断。只记录工具调用，不把协议握手、健康检查或未认证请求冒充调用。
- 参数与结果只保存白名单摘要，不保存密钥明文、正文、图片、完整下载地址、签名参数或原始异常。系统记录只读，不参与 Ledger 修正。
- 草稿调用可查看当前草稿状态及人工入库节点；学习节点可返回来源调用。没有调用历史的旧草稿明确缺失。
- 窄屏在列表与详情之间切换，深浅主题均使用现有 token 和组件。

## 4. 实施计划与关键决策

1. 用独立 SQLite 存储记录 MCP 调用生命周期；接入工具执行边界和主服务启动恢复，保持原权限、原图、幂等和共享写锁契约。
2. 新增受 Web 登录保护的运行记录读取接口；服务端筛选后分页，统计覆盖筛选全集，详情复用草稿和 Ledger 标识。
3. 实现分区时间线和详情面板，复用既有历史修正请求；加载失败保留旧列表，迟到请求不覆盖当前筛选或卸载页面。
4. 运行有意义的存储、权限、并发、脱敏、真实 SDK 和浏览器验证；补文档和日志，完成全部门禁后提交。

默认查询全部时间，避免旧学习记录被日期过滤隐藏；草稿中的最近七天作为可选筛选。调用存储失败不改变已授权业务结果，固定诊断消息不泄漏输入；接口读取失败明确报错。

## 5. 边界与修改范围

覆盖空记录、非法筛选、重复请求、部分提交后失败、调用中吊销、重启中断、旧草稿、筛选切换竞争和分页失败。可以调整页面文件拆分与测试定位器；不改学习算法、权限、正式入库流程、侧栏导航、其他页面或版本号。不部署、不推送，不操作真实 Vault。

## 6. 验收与验证

真实临时 Vault 中由官方 SDK 完成查询、失败、草稿创建和幂等复用，Web 页面能筛选并查看真实记录及人工入库关联。旧历史修正、分页、撤销和恢复仍正常；重启中断可追踪；数据库中无输入秘密和原图内容。

必跑：Python 相关专项及全量、`node --test tests/app/*.test.mjs`、`python3 tests/app/run_browser.py`、`python3 tests/e2e/history.py`、`python3 tests/e2e/mcp.py`、`python3 tests/check_ui.py`、`python3 tests/check_contrast.py`、`python3 tests/visual/run.py --ref 968fdfb --pages history`，以及 `python3 tests/check_docs.py --write-routes --write-log-index` 和 `python3 tests/check_docs.py --diff 968fdfb`。页面和协议验证均用临时 Vault、随机高端口，启动环境去掉 `OMRS_SYSTEMD_SERVICE`。

## 7. 执行原则

先读后改，以代码为准，不做无关重构。只在无法判断的数据冲突或需要生产变更时停下；其余连续执行到验收和提交。中断后读取 Git 状态、最近提交及进度状态块继续。最终中文汇报提交、已执行验证、未执行验证、遗留与下一步。
