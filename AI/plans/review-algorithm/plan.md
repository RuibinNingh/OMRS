# 复习算法：一次击杀、分档复核

执行者：Codex；运行模式：完整模式。终点为本地实现、隔离验证及提交；生产部署、推送和真实题库重算需要另行授权。

## 用户原话与目标

> 改革OMRS的复习算法
> 取消必须连续两次高分才算击杀的规则
> 有方案吗?中途可以询问我

用户已确认：一次高分答对即可击杀；复核采用7、21、60、120、180天；已击杀题低分答对退出击杀、3天后巩固；既有历史按新规则重算。

## 最终行为

| 场景 | 状态与排期 |
|---|---|
| 普通题高分答对 | 立即击杀，第1档，7天后复核 |
| 已击杀题到期高分答对 | 升一级，从本次复核日起安排下一档；最高档循环180天 |
| 已击杀题提前高分答对 | 记录练习，档位与原定日期不变，不增加累计击杀次数 |
| 已击杀题低分答对 | 退出击杀、磨合中，档位归零，3天后巩固 |
| 已击杀题答错 | 待攻克，档位归零，1天后重练，沿用现有熟练度降级惩罚且不重复相乘 |

高分阈值默认7，仍可调。逾期再久也只升一级。重新击杀从7天起步；累计击杀次数保留但不决定周期。普通题保留现有SM-2、EF和推荐优先级，非击杀态熟练度上限0.95。

## 实施与兼容

1. 唯一反馈转换统一负责网页反馈、助手预览、增量投影与完整重放。
2. 投影新增复核档位、周期起始日期；due_date保存实际排期。最后练习时间可更新，提前练习不能推迟排期。
3. 设置移除击杀连对和旧复燃计算参数，增加五个严格递增正整数的间隔配置，默认[7,21,60,120,180]。旧参数兼容读取但无效，保存时清理。反馈请求不变，题目响应增加档位，next_revive_date为实际日期。
4. 反馈显示结果和日期；题库、详情与调度显示档位和复核日期。到期复燃进入推荐、待复习和逾期提醒，未来复核计入预测，休眠题不进常规推荐。
5. 升级投影版本并重放全部有效反馈，不改不可变Ledger。只有旧导入快照的题从第1档迁移：有效最后复习日加7天；无可靠日期的旧击杀题待复核并入队，首次高分后从7天起步。失败不发布部分状态。
6. 同步映射文档、任务日志及进度。保护工作区原有导出改动；不做无关重构。

## 验收和提交

- 验证一次高分击杀、阈值边界、五档与最高档循环、提前练习不延期、逾期只升一级、低分/答错降级与重新起步。
- 同日多次反馈、撤销/替换/恢复、重启和完整重放一致；旧配置、旧快照、无日期及日期上限正确；原始记录完整。
- 临时Vault、随机高端口，移除OMRS_SYSTEMD_SERVICE及OMRS_BOXDETECT_CONTROL；真实浏览器走反馈→击杀→到期推荐→复核→降级，并查设置、题库、仪表盘及复盘。
- 运行后端、Node、组件浏览器、相关页面E2E、文档/UI/对比度及视觉比较门禁。计数只写实际结果。
- 作为一个完整垂直切片提交代码、测试、文档、日志及进度，不纳入原有改动。
