# MCP 新题 SVG 配图执行计划

执行者：Codex；运行模式：完整模式。

## 用户原话与目标

- 「适配一下」
- 「允许创建题目的时候附上svg」
- 「然后更新mcp说明,使其符合事实」
- 输入方式已选「源码和文件都支持」。
- 用户批准实施：「Please implement the plan.」

新题可携带SVG源码或文件，按阅读顺序经过草稿审核入库，保留向量原件；工具说明与真实能力一致。

## 已批准契约

create_draft新增kind=svg、svg源码块；images支持.svg文件，仍用image下标引用并统一为SVG块。题目或答案均可插图；两种方式合计最多3个SVG块、每张256KiB，沿用40块与6个上传附件预算。复用正式题目的安全白名单、白底及90mm双栏可读性校验。

SVG原始字节与来源位图分开保存，草稿存储增量迁移。source_images只含位图，get_draft返回配图元信息；get_draft_image新增block_id，与image_index二选一，SVG返回PNG派生图。创建摘要、事务、失败回滚和人工入库覆盖SVG；原件不得转成截图。

审核页按原顺序显示配图、检查信息与人工核对提示，只读源码，可改说明、调序、移动或删除。SVG不裁框、不转文字、不参与训练。正式创建复用现有SVG附件与Obsidian引用能力；审批、版本及权限保持。

## 实施与验收

1. 接通MCP输入、独立存储、查询和入库恢复，覆盖旧草稿兼容与幂等。
2. 接通审核预览、暂存、刷新和移动，更新真实工具schema、instructions及可执行示例。
3. 用官方SDK与真实浏览器验证源码/文件、位图混排、两节插图及向量PDF；执行适当后端、Node、组件、UI、对比度、视觉和文档门禁。
4. 同步模块文档、日志与本进度，以一个完整功能切片本地提交。版本保持，不包含部署或推送。

只在无法安全区分已有改动或必须改变已批准契约时停止；其它情况连续执行到本地验收与提交。中断恢复先读progress.md和git状态。最终中文汇报提交、已执行与未执行验证、遗留和下一步。
