## 3. 最终预期行为

### 科目概况

`subject` 省略或为空字符串时保持当前全局语义；指定科目时所有汇总、明细和 `summary` 都只来自该科目。同一数据与日期下，助手直接查询和真实 MCP 查询结果一致。未知科目返回零计数、零平均值及空列表，不能回退到全库。

统计口径按当前 `get_stats`、`due_info`、`is_killed_state` 等规则确定，不另造算法：

| 字段 | 科目范围内的计算口径 |
| --- | --- |
| `total` | 未停用题数 |
| `suspended` | 停用题数，必须在剔除停用题之前计算 |
| `overdue/due_today` | 未停用、未击杀且有有效到期日的题，分别判断小于今天/等于今天 |
| `killed` | 未停用题按当前击杀判定计算 |
| `leech` | 沿用当前顽固题判定，排除停用/已击杀题 |
| `fresh` | 未停用且练习次数为 0 的题 |
| `avg_mastery` | 所有未停用题的原始未衰减熟练度之和除以 `total`，最后保留 3 位；不先舍入单题，不以“已练题”作为分母，不使用 `mastery_of` 的 `None` 替代值 |
| `weakest/leeches/summary` | 全部限于相同科目；保留既有弱分类分母、排序、条数限制与文案结构，摘要使用过滤后的计数 |

### 并发与权限

首次初始化和旧库迁移由同一受锁保护的入口串行；不同请求可正常建各自草稿，相同请求仍只创建一份。下载不占全局写锁。

Key 在图片处理或等锁期间吊销、到期或失去 `draft:create` 时，新建前和幂等结果封装返回前均重新验证。拒绝的复用请求不返回草稿正文，不改变已有草稿或原图。仅建草稿 Key 复用自己的请求仍使用 `draft:create`，不额外要求 `omrs:read`。

`tools/list` 每次按当前 Key 的实时 scope 返回工具：`omrs:read` 为既有九读，`draft:create` 仅为 `create_draft`，两者兼有为全部十项。调用端继续独立校验，知道隐藏工具名也无权调用。

### F2：串行化草稿库迁移

在 `omrs/drafts.py:connect` 的初始化/迁移段集中取得既有全局写锁和草稿模块锁，失败关闭连接；成功后保持原连接 API。检查所有调用方锁顺序，不只给 MCP 一次预热。涵盖没有数据库的新库和缺列旧库。补 `tests/test_mcp_draft_atomic.py` 的确定性交错与 `tests/test_mcp_protocol.py` 的首次并发创建。

同时梳理 `omrs/mcp/server.py` 的 `_MCP_CREATE_LOCK`：默认去掉重复串行锁，让最后的幂等复查及原子创建依靠领域层的全局写锁/草稿锁；不要保留“先 MCP 模块锁、后全局写锁”的反向嵌套。此调整只支撑 B2/B3，不扩展为全站锁重构。

### F3：补齐幂等返回的鉴权

依赖 F2 的锁边界，在 `omrs/mcp/server.py` 收敛两处幂等成功返回和新建前的权限检查。下载/校验之后、实际写锁取得之后复查新建权限；URL 快速复用及下载/inline 复用都在返回结果前复查。用事件控制吊销、到期、scope 变化的时点，覆盖等待锁和等待迁移的窗口；保留过期签名 URL 免重下载与 inline SHA 校验。

### F4：按 scope 发现工具并完成回归

在 `RestrictedMCP` 增加请求级工具发现过滤，定义一份显式工具到 scope 的固定映射，发现和调用共用它。底层注册表仍保持完整；不可按某个客户端删除全局工具或依赖 SDK 的共享工具缓存授权。补两个客户端交错发现、直接调用隐藏工具、同客户端权限变化等测试，保留 fileParams/schema/annotations。

## 5. 关键技术决策

- **统计：**默认给现有统计入口增加可选科目范围，由共享助手查询调用，MCP 不维护第二套聚合。先取得科目范围，再按现有原始行/投影口径区分停用和活动题；相关练习历史按范围内有效身份过滤。平均值最后舍入，击杀判定使用原始熟练度；全局调用的签名兼容与结果保持。科目名仍精确匹配，不新增别名或搜索逻辑。
- **迁移：**默认在数据库初始化入口集中锁定，保证从助手、Web、MCP 进入都受保护；仅在服务启动预热不能覆盖其他懒初始化调用。锁顺序为全局写锁在外、草稿锁在内，锁仅覆盖同步初始化/领域事务；持 `threading.RLock` 时不跨 `await`。锁超时复用现有 `write_busy`，不吞掉列冲突重试充当修复。
- **幂等：**保留 `(source_key_id, request_id)`、实际内容摘要、稳定文件身份及冲突规则。复查不覆盖草稿、复活已丢弃草稿或清除原件；新建事务仍只写草稿存储。
- **鉴权时点：**以实际副作用前和结果封装前最后一次检查为准；不承诺与网络响应送达原子化，也不撤销已经合法提交的草稿。若提交后 Key 失效，响应可拒绝，但已提交草稿与原件必须保留；相同 Key 以后恢复有效时仍可幂等复用。
- **错误：**请求开始时无效 Key 保持 HTTP 401；处理中复查失效沿用工具权限错误，`isError=true`、稳定 `forbidden`，不附草稿正文。未知工具/参数/冲突/锁忙的既有语义保持。
- **发现与缓存：**每次从有效 Key 的实时 scope 过滤返回描述，不修改全局注册表；授权不能借 SDK 的工具定义缓存继承。创建工具的元数据和注解保持原值，只读 Key 不发现它。
- **兼容：**不新增 schema、持久化列、配置键、HTTP 路由或依赖，不迁移真实数据，不变更版本号。原助手权限、PIN、训练、原图与人工审核边界保持。

## 6. 边界情况

- 空库、未知科目、仅停用题、没有已练题；多科目状态不同，空/非法到期日、击杀题保留旧到期日，冻结“今天”避免跨日误差。
- 新库同时建不同请求/相同请求；旧库缺列同时迁移；助手与 MCP 同时进入存储；初始化失败、锁超时及重试，等待必须有限时。
- 纯文字/URL/inline/混合图重试；URL 更新或过期，inline 内容改变，同一 request_id 异内容；人工已经编辑、入库或丢弃原草稿。
- 创建及复用过程中吊销、到期、scope 变化；发生在处理开始前、图片校验中、等锁期间、返回前；提交后失效不删除已提交数据。
- 只读/仅建草稿/双 scope 客户端交错发现和调用；隐藏工具被点名调用，Key 吊销后的旧客户端，以及 SDK 缓存已存在其他客户端工具描述。
