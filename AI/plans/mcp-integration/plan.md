# OMRS MCP 接入计划

## 目标

把 OMRS 内置助手的查询能力和创建草稿能力，以受限 MCP 接口提供给外部对话助手。使用 API Key 管理权限；MCP 唯一业务写入是创建草稿；来源必须标识 MCP；用户在现有草稿工作区审核后才正式入库。上传图片保持完整，不做框选、裁剪、标注。

## 架构决定

复用查询与草稿领域逻辑，不启动 OMRS 内部的模型对话循环。建立独立 MCP 能力白名单，不能把助手整个注册表暴露出去。

当前采用已实现的同进程 SDK：OMRS 主进程完成 API Key 校验、权限判定、数据访问和草稿写入，同步领域操作在线程内执行，沿用进程级写锁。本批保持该架构，补齐初始化、幂等返回与工具发现的边界；不改成第二进程直接写同一个 Vault，也不将普通 HTTP API 变成任意转发代理。

原规划允许以同进程托管代替薄适配进程，实施选择已记在 `progress.md`。外部 SDK/客户端与生产/账户的实际验证状态分开记录，修复不代替账户联调。
