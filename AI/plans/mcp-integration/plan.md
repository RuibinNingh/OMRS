# OMRS MCP 接入计划

## 目标

把 OMRS 内置助手的查询能力和创建草稿能力，以受限 MCP 接口提供给外部对话助手。使用 API Key 管理权限；MCP 唯一业务写入是创建草稿；来源必须标识 MCP；用户在现有草稿工作区审核后才正式入库。上传图片保持完整，不做框选、裁剪、标注。

## 基线与证据

- 仓库：`RuibinNingh/OMRS`。
- 调查基线：`main` / `db73c7e14925fd490ba094bc82012073e4c92d9b`，2026-10-01 通过 GitHub 读取。
- 本次完成的是静态代码与文档调查；没有运行测试、修改 GitHub 仓库或连接生产实例。
- 完整需求、函数定位、技术决策、分期和验收见 `exec-2026-10-01-mcp-v1.md`。

## 架构决定

复用查询与草稿领域逻辑，不启动 OMRS 内部的模型对话循环。建立独立 MCP 能力白名单，不能把助手整个注册表暴露出去。

默认采用薄 MCP 协议适配进程，加 OMRS 主进程内的受限调用入口。适配进程不直接读写 Vault；主进程完成 API Key 校验、权限判定、数据访问和草稿写入，以继续使用现有进程级写锁。不得将普通 OMRS HTTP API 变成任意转发代理。

外部 SDK/客户端兼容性在 P0 验证。若维护者选择同进程托管 SDK 以减少部署进程，可以在进度中记录实现调整；必须证明共享同一写锁、异步执行不破坏锁语义，并且不改成第二进程直接写同一个 Vault。

## 分期

| 阶段 | 交付 |
| --- | --- |
| P0 | 实际 ChatGPT 接入方式、API Key 传递、文件参数、SDK 版本和传输兼容性验证 |
| P1 | 共享查询/草稿逻辑与显式能力白名单；原助手回归不变 |
| P2 | API Key 生命周期、受限主进程入口与 MCP 协议适配 |
| P3 | MCP 草稿来源、外部错因证据、完整图片、原子创建与重试去重 |
| P4 | 现有设置页和草稿工作区接入，来源展示及审核流程 |
| P5 | 权限、并发、故障恢复、浏览器与真实客户端验收；部署说明 |

## 不做

不提供正式建题、改题、反馈、练习/Session 创建、标记修改、草稿修订/丢弃/入库、设置修改、任意文件/SQL/HTTP 调用工具。不开发第二个推理 Agent、不新增自动 OCR/框选、不重写前端、不做模糊重复题系统、不发布公共插件、不改生产服务。

## 完成标准

鉴权与文件传递完成目标客户端实测；允许工具与直接调用均符合白名单；查询复用同一数据口径；每次创建只产生可审核的 MCP 草稿；图片完整；重试不重复建草稿；旧助手和人工审核流程正常；测试记录真实可追溯。仅本地 Inspector 通过不等于 ChatGPT 端到端完成。
