## 1. 任务目标

主目标：用户能在 AI 助手里贴截图，主 AI 按设置直接看图或看转述，并能把一道题录成**草稿**（存在 `错题/.omrs/drafts/`，不进 Ledger）。

必须同时满足：

- `agent_vision` 开时图片以 `image_url` 进主模型，关时由转述模型转成文字再进主模型；两种模式都有 `describe_image` 工具；
- 新工具 `create_draft` 自动执行、不写 Ledger，错因只能带着用户原话写入；
- 下线 `create_text_question`；
- 助手输入框支持粘贴、拖入、选择图片；设置页有「主 AI 支持图片」开关；
- 收件箱、快速录入与助手其余工具行为不变。

草稿区界面、入库、角标、框选属于 P2–P4，本期不做。

用户原话（完整清单见 `plan.md` §0）：U2 "发给主 AI 一个截图……主 AI 用工具自己创建题目，答案解析，错因（要用户提供）"；U9 "设置里面设置AI是否支持图片,如果不支持会走模型转述"；U10、U11 "草稿不进Ledger,独立管理"；U14 "先不做让ai改功能"。

## 3. 最终预期行为

**用户可见：**

1. 助手输入框：Ctrl/Cmd+V 粘贴图片、拖入图片、点回形针选图，输入框上方出现缩略图条（可删除单张），最多 6 张。发送后，用户消息气泡里显示这些缩略图，标注 IMG-1、IMG-2…（在同一对话内连续编号）。
2. 设置 → AI 助手：新开关「主 AI 支持图片」，说明文字：「开：图片直接发给主模型。关：先用『AI 识别』里的转录模型把图片转成文字。」
3. 关视觉模式时，运行开始后运行卡片里先出现「转述 IMG-1…」步骤，完成后主模型才开始回答；同一张图再次出现时不重复转述。
4. 用户说「录一下这道题」，AI 调 `create_draft`，工具卡片显示草稿编号、科目 / 分类、题目前 60 字、各块类型（文字 / 图片）和状态（待审核 / 待框选）。不弹确认。
5. 用户没说错因时，AI 追问；用户说了，草稿里的错因就是用户说的话。

**核心逻辑与数据流：** 见 `plan.md` §3.1。本期实现到「create_draft → 草稿状态」为止。

**必须保持不变：** 纯文字消息的请求与存储格式（没有图片时 user 消息仍是 `{"role":"user","content":text}`）；按运行撤销；其余 16 个工具；收件箱全部接口。

## 5. 关键技术决策

**D-P1-1 图片校验。** 只收 `data:image/(png|jpeg|gif);base64,`；解码后 ≤8MB；用 `inbox.image_size()` 取宽高，取不到视为非法。存为 `images/<sha256>.<ext>`。超限或非法：400，错误写明是第几张、原因。

**D-P1-2 IMG 编号。** 每个对话从 1 开始连续递增，存在 `conv_images`；同一对话里重复贴同一张图沿用旧编号。编号对用户和模型都可见，是工具参数里引用图片的唯一方式；模型永远拿不到 sha 或路径。

**D-P1-3 `describe_image`（read）。**
```
{"image": "IMG-n", "question": "要看清的具体问题"}   question ≤300 字
→ {"image":"IMG-n", "answer": "…≤2000 字"}
```
用 `_ai_config(vault, "extract")` 与 `_call_model`；视觉模式下也可用（主模型想要更细的局部识别时）。

**D-P1-4 `create_draft`（rev）。**
```json
{
  "subject": "…", "category": "…",                    必填，规则同现有录题工具
  "knowledge_points": ["…"],                          ≤8
  "images": ["IMG-1", "IMG-2"],                       这道题用到的截图，可为空
  "blocks": [                                         ≥1，且至少一个 section=题目
    {"section": "题目|答案", "kind": "text",  "text": "…$LaTeX$…"},
    {"section": "题目|答案", "kind": "image", "image": "IMG-1", "note": "图在截图中部的几何图形"}
  ],
  "cause": "…", "cause_statement": "用户原话"          cause 非空时 cause_statement 必填
}
→ {"draft_id","status":"review|cropping","subject","category","blocks":[{"section","kind","image?"}]}
```
- `kind=image` 的块必须引用 `images` 里列出的图；`images` 里的每个 ref 都要能在本对话解析。
- 难度固定 5，标记不由 AI 填（同现有约定）。
- 块按数组顺序定 `ord`；同一 `section` 允许多个块。
- 草稿记下 `conversation_id / run_id / tool_call_id`（来自 `omrs/actor.py` 的当前 actor 或工具上下文，先定位工具函数的 `ctx` 里有什么）。

**D-P1-5 错因原话校验。** 把 `cause_statement` 与本对话所有 user 消息的 `content` 做同样的规范化（NFKC、去空白），`cause_statement` 必须是其中某条的子串，且长度 ≥2。不满足时工具返回错误「错因只能用用户说过的话：没在对话里找到 cause_statement」，草稿不建。`cause` 本身可以是对原话的整理（例如去掉口语词），但不能在没有原话时出现。

**D-P1-6 提示词新增规则**（`system.md`，是说明不是防线）：用户要求录题才建草稿；先判断题目、答案各自能否完整转成文字，不能的部分用 image 块并在 note 写明位置；一张截图里有多道题就分别建草稿；错因只用用户原话，用户没说就先问，用户说「不填」就留空；录好后告诉用户草稿编号和状态；不要在草稿里写解析以外的聊天内容。

**D-P1-7 写锁。** `/api/agent/message` 现在在写锁豁免清单里（只写 `agent.db`）。本期它也写 `drafts.db` 与 `drafts/images/`，同样不碰 Ledger：更新 `omrs/locking.py` 豁免理由为「只写 agent.db 与 drafts.db（各自带连接锁）」。`create_draft` 在运行线程里执行，工具执行期间照常持有写锁（现有钩子行为），无需改动。

**D-P1-8 兼容。** 老对话没有 `_images`，行为不变；老的 `create_text_question` 工具调用记录仍能在界面重放（工具卡片对未知工具已有兜底，确认一下）。

## 6. 边界情况

| 情况 | 处理 |
|---|---|
| 只发图不发字 | 允许；模型收到的文字为空加图片（或转述） |
| 运行中带图插话 | 409，前端保留输入框里的图片与文字 |
| 同一张图贴两次 | 同编号，只转述一次 |
| 转述模型没配或调用失败 | 运行继续，注入失败说明；设置页 AI 识别未配置时，关视觉模式下发图，前端在发送前提示「转述模型未配置」 |
| 视觉模式但模型不支持图片（上游 400） | 运行以 error 结束，错误原文里带上游信息；运行卡片提示「可在设置里关掉『主 AI 支持图片』改用转述」 |
| 对话被软删除 | 图片与草稿保留（草稿区 P2 仍可见）；本期不做清理 |
| 服务重启 | 已存的图片、转述缓存、草稿都在库里；中断的运行按现有 `interrupted` 处理 |
| 60 条消息上限 | 不变；带图消息算一条 |

## 10. 执行原则

- 先读后改；以代码为准，本说明里的函数名与代码不符时按代码实际结构落实，目标、接口契约与验收不变。
- 复用收件箱和 `ai_assist` 的现有函数，不复制粘贴一份改名。
- 不做无关重构。
- **停止条件**（其余情况一律连续执行）：
  1. 阶段 0 门禁有失败且失败涉及 `omrs/agent/` 或 `assistant` 相关测试；
  2. 发现 `create_text_question` 在助手以外还有调用方（下线会破坏别处）；
  3. 视觉模式的 `image_url` 必须改 Ledger、收件箱表结构或 `create_question` 才能实现；
  4. 真实模型走查时，两种模式都无法让模型正确调用 `create_draft`（记录原文后停下，交规划者调整提示词或工具设计）。
- **会话中断后恢复**：读 `progress.md` 与任务日志，`git log` 找到最后一个 `ai-draft P1-*` 提交，从下一步继续。
- **最终汇报**：五个提交的哈希与标题；门禁计数对比基线；真实模型走查结果（或跳过原因）；偏差与遗留；P2 规划需要知道的事实。
