# 统一 AI 审核中心与 MCP 改题计划

执行者：Codex，完整模式。基线：eda4510。用户已在聊天批准本计划并要求完整实施；终点为本地实现、验证、文档与提交，不包含生产变更、推送或版本升级。

## 1. 目标与已确定的边界

新增独立「审核中心」，集中处理 MCP 和内置 AI 助手的业务写操作，完成待审、执行、结果与来源追溯，同时开放经过人工审核的 MCP 正式题目编辑。

> 但是需要新增一个审核区域
> 我不知道放哪合适,难道要新开一个区域吗?

>
> 新增一个审核中心吧

> 审核包括MCP
> 还有AI助手操作
> 操作不包括读,只有写(修改)
> 制定计划,检查安全修改方案,顾全大局

除已被新决策替代的位置疑问与已完成调查外，上述均为明确要求。后续选择：按影响分级；仅 MCP 与助手；助手实时等待十分钟；接入可核实旧记录；MCP 修改正文和常用题目信息；正式题目提案可人工修正后通过。

## 2. 最终行为与审核规则

审核中心导航紧邻助手、始终可见，提供待审核与操作记录，按来源、类型、状态、时间筛选。

| 来源与操作 | 处理规则 |
|---|---|
| MCP、助手建/修订草稿；助手聊天练习卡 | 自动执行并记录 |
| MCP 新报告、普通展示板管理 | 自动执行并记录，触发高风险条件则审核 |
| 两来源创建正式复习计划 | 执行前审核 |
| 助手改正式题目/知识点/标记、移动/停用/恢复、反馈、建分类、确认草稿入库 | 执行前审核 |
| MCP 新正式题目修改 | 执行前审核 |
| MCP 删除板/文件夹、清空非空板、重置既有纸面记录 | 执行前审核 |
| 查询、图片读取、转述缓存、运行日志、导出下载快照 | 不进入中心，原运行历史仍可追溯 |

服务端固定分类，未分类新工具不得执行业务写；参数不能降低审核级别。

录入页 AI 草稿改为跳转，现有图文审核能力迁入中心。草稿无十分钟时限，同一草稿只计一次；创建、修订和入库调用可分别留记录。聊天与中心决定相同操作，旧草稿/确认链接兼容。批准与执行分开显示，拒绝/到期/冲突/中断/失败/部分成功/无变更如实展示。

桌面列表与详情，手机切换及上下对照；本批不提供批量通过。后台 OCR/框选不单列，但草稿详情保留现有状态与作业。

## 3. 实现方案与接口

新增 ai_review.db 为唯一审批权威，存原请求、目标快照、提案版本、实际执行内容、来源/决定/领域回执。业务事实留在原 Ledger、草稿、展示板、报告库。旧 MCP 接口只代理；自动写也先登记意图，登记失败拒绝新写，提交后记录失败根据原生回执收束。

历史按稳定源身份幂等导入，结合事件、工具记录、Ledger 与回执；不确定显示历史信息不完整，不伪造来源、审核人或成功，不重新批准旧历史。

| 接口 | 契约 |
|---|---|
| GET /api/ai-review/items | view=pending/records，来源/类型/状态/时间筛选，cursor 分页 |
| GET /api/ai-review/detail | id 操作详情 |
| GET /api/ai-review/counts | 去重待审数量 |
| POST /api/ai-review/update | id、expected_revision、patch，仅待审允许字段 |
| POST /api/ai-review/decide | id、expected_revision、approve/reject |

接口沿用 Web 登录/同源、可信身份，MCP Key 不能调用审批。

助手保留原线程十分钟等待：决定持久化后唤醒，等待不持业务锁。修订递增版本/摘要/票据，旧码失效，不续期限。批准后不能修订，执行固定最终内容并向模型返回实际用户修订结果。保留 actor、预算与运行撤销。拒绝/到期/停止共享终态，重启旧助手等待失效，不自动续跑模型。

新增 propose_question_update，须 question:propose 与 omrs:read，新权限默认关闭。读取补稳定 question_id 与可编辑信息。输入稳定身份、expected_content_hash、patch、修改原因、request_id；输出待审编号、预览、中心链接，原查询能力读状态。

允许题干、答案、错因、备注、知识点、难度 1–10 和已有标记。禁止整篇 Markdown、系统 YAML、学习状态、成绩、路径、移动、删除、附件增删。note 仅管理 #备注 下 ##补充备注，旧陌生文本/子节、错因、关联原样保留。分节与 YAML 防注入；两种图片引用的原 token、数量、顺序和章节保护，禁止外链等图片旁路。

人工只能改本操作允许字段，不能改身份/权限/来源/基线/request_id；原请求摘要独立于人工摘要，重试不覆盖人工版本。

MCP 正式计划响应改为先待审，不立即创建 Session。旧已执行请求返回原回执，被撤销不复活；拒绝/到期须新 request_id。同步工具说明、SDK、界面与文档。

## 4. 必须通过的安全检查

调查在临时 Vault 实测：备份恢复后的旧待审可执行删除；恢复的 applying 会被运行记录 GET 重放。两条都必须建立旧实现失败的回归并修复。

- 整库恢复显式废止新旧库未终结审批，匹配回执只还原既有事实，不还原权限；不只比较数字世代。
- 审核/状态 GET 不做业务重放，恢复在明确启动阶段执行。
- 决定与实际执行都复核权限、期限、身份、磁盘哈希/版本、配置及停止状态。
- 修订/批准 CAS 互斥，两个页面只产生一项有效决定。
- 锁顺序：租约 → 全局写锁 → 确认对象锁 → 存储，更新确认/停止的锁豁免理由。
- 正式文件写增持久意图、原子替换、同事务 Ledger 回执；无事实不盲重放。回滚须身份/世代/路径/哈希与无后续事实全部匹配。
- 批量写逐项显示结果，不能把批准当整批提交或盲重放。
- 完整内容只在保护存储/详情，运行日志继续脱敏，不存 Key/PIN/Cookie。
- 同页换目标、筛选、切页、前后退均保护未保存输入，刷新不覆盖；草稿变化废止旧入库快照。
- 复用现有能力，页面间不得互相 import，仅抽出实际共用组件。
