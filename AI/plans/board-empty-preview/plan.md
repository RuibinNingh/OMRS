# v2.8.4：修复展示板空板预览误报

## 目标与依据

执行者：Codex，完整模式。用户原话：「那么制定修复计划」「版本号+0.0.1」，随后明确要求实施本计划。

修复空板预览误报，将 v2.8.3 升至 v2.8.4。基线为 94fa3b2，保留原有 AI/plans/omrs-maintenance/validation.json 未提交改动。

已实测：空板导出返回 500，浏览器显示「预览生成失败」；有题板正常生成一页预览。规划时现有展示板 Node 测试 125 项通过，Python 测试 51 项通过。

## 页面修复

- 统一判断当前有效打印范围内是否有可打印题目：排除缺失、停用题；仅新增模式再排除已印题，沿用现有范围选择规则。
- 无可打印题目时停止请求预览。真正空板显示「板里还没有题，添加题目后可预览」；全部停用或缺失时显示「当前没有可打印的题目」，保留列表中的原因提示。
- 清空最后一道题，或从有题板切到空板时，立即撤下旧纸面、清除页码和预览错误，取消在途请求及延迟任务，使旧消息失效。保留常驻 iframe 节点和固定 morph 边界。
- 加入有效题目后自动恢复预览，无需刷新页面。
- 打印、下载共用空内容检查；按钮禁用，菜单或快捷键触发时给出提示，不发导出请求、不打开打印窗口。
- 为预览成功及失败回调增加请求归属检查，防止旧板的结果污染当前板。真正的网络或生成异常继续显示错误及具体原因。

主要修改展示板控制器、预览生命周期、视图模型与打印协调模块，复用现有样式和组件。

## 后端错误语义

- 为展示板的三种可预期情况统一返回 HTTP 400：没有可导出的题目、没有新增题目、请求续印但没有纸面记录。
- 使用专用业务异常，继承现有 RuntimeError 并携带 status=400，复用服务器现有异常处理。未知异常仍返回 500。
- 错误响应保持现有 {status:"error", msg:"…"}，成功响应继续返回自包含 HTML；无需新增接口或数据迁移。
- 同步纠正文档中「返回 400」与当前代码不一致的描述。

## 验收与验证

1. 初次打开空板、全部停用或缺失的板：无错误红字，无预览导出请求，空状态清楚。
2. 空板加题、删除最后一道题、快速切板，以及旧请求延迟成功或失败：纸面、页码和提示始终属于当前板。
3. 打印和下载所有入口都能拦截空内容；直接调用接口返回约定的 400。
4. 模拟网络中断及真实生成异常：错误仍能显示。
5. 整板打印、增量续印、纸面记录、保存队列及几何调整零导出请求的行为通过回归。
