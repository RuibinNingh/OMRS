# OMRS 2.0.0：审核优先与移动端工作流升级计划

> 状态：已完成源码调查和规划；业务实现、测试、部署均未执行。
> 调查日期：2026-09-29。
> 仓库：RuibinNingh/OMRS；锁定 main 提交 `1d082194ad959aaf6d754a90ed95db9183484adc`，`omrs/version.py` 为 `v1.35.0`。
> 目标发布：`v2.0.0`。执行者建议为 Codex（完整模式）；生产部署另行授权。
> 证据性质：GitHub 源码、同提交模块文档和用户截图的静态核对。没有运行测试、启动网站、测量交互耗时或验证用户设备上的计算样式。文中的尺寸、点击次数和性能要求均为拟定验收目标，不是已测结果。
> 本包是计划文档，不是应用源码包或已经应用的补丁；没有修改远端仓库。

## 1. 任务目标

将 OMRS 从“流程信息很多、用户反复寻找操作”调整为“审核题目、保存入库、随时练习”的工作台。保持现有本地 Markdown 题库、Ledger、草稿数据库、原生 ES Module 前端和训练模型边界，不进行换框架式重写。

用户需求对照：

| 编号 | 用户原意 | 交付点 |
|---|---|---|
| R1 | AI 草稿核心应是审核，手机滚动过长，电脑也费劲 | 审核优先布局、逐题队列、必要时才编辑或框选 |
| R2 | 快速录入截图区不居中 | 修复选择器冲突，并压缩空状态 |
| R3 | 助手不能拖拽文件，自己上传的图片直接跳转 | 聊天主区域可拖图，站内图片预览 |
| R4 | 手机助手别扭、效率低 | 键盘适配、单层头部、紧凑输入、信息折叠 |
| R5 | AI 创建分类、修改草稿；聊天中有不属于正式 Session 的临时练习 | 分类工具、版本化草稿补丁、聊天练习卡 |
| R6 | 删除笔记本页码 | 删除活动入口和新写入；保留不可变历史，不误删备注 |
| R7 | 历史卡片信息量不足 | 面向学习内容的摘要与变化展示 |
| R8 | 题目面板错因等字段自动识别 | 证据化识别、字段级补全、人工优先 |
| R9 | 快速录入不允许 AI 修改标记 | 提示词、响应白名单、前端合并三层禁写 |
| R10 | 下拉、展开列表像浏览器默认样式 | 共享选择器与折叠组件，完整键盘交互 |
| R11 | 助手圆环显示缓存占比，详情显示缓存占比和本次总 token | 明确分母、跨轮累计、缺失值语义和辅助调用统计 |

## 2. 当前背景与约束

### 2.1 已确认的源码事实

1. **草稿信息顺序确实偏向加工而不是审核。** `features/create/drafts-view.js::detailView()` 依次渲染来源图、canvas、字段、内容块。`drafts.css` 已有 sticky 页脚，所以不能把“新增固定页脚”当成主要改进。来源图和训练仍有作用，但不应占据审核首屏。[S1]
2. **截图区存在明确的 CSS 覆盖。** `ui/filedrop.js` 用 `<label class="ui-filedrop">` 包装；组件 CSS 为 flex 居中；`features/create/create.css` 的 `.crw-pane label` 将其改为 grid。`styles/index.css` 中 features 层晚于 ui 层。改后仍须在真浏览器查看 computed style 与截图。[S2]
3. **助手不是完全没有拖拽代码。** `assistant/index.js` 只处理落在 `.ast-composer` 的拖拽；现有接收链路是 PNG/JPEG/GIF 图片，不是任意文档解析器。`openImage` 调用 `window.open`；已发送图片也走外部打开式入口。[S3]
4. **手机版不是完全没有响应式。** 已有抽屉和断点；主要问题在外壳与聊天区域叠层、`100dvh - --ast-chrome` 固定扣高、输入区占位、建议与统计常驻。不能只加一个窄屏 media query。[S3]
5. **分类目前允许在建题时出现新名称。** `classify_question` 提示词允许合适时建议新分类；`creation.py::create_question` 创建分类目录与锚点文件。但 `collect_taxonomy()` 主要从已有题目投影读取分类，因此“显式创建零题分类并在各入口可见”还没有独立闭环。[S4]
6. **AI 草稿工具缺少编辑能力。** `omrs/agent/tools/drafts.py` 有 create/list/get，但没有 update 工具；`get_draft` 的块输出没有完整稳定块标识与编辑所需信息。存储和人工编辑已有 revision/CAS，应复用，不另造无版本接口。[S5]
7. **即时练习已满足不创建正式 Session 的基础要求。** `features/instant/index.js` 从推荐组队列，再向 `/api/feedback` 提交 `IMM-*`；不调用正式调度创建。缺的是接收聊天生成的明确题序与稳定卡片引用。[S6]
8. **“页码”和“备注”同名不同义。** quick 的 `form.note` 通过 create payload 进入 Markdown `页码:` 和 metadata；题卡使用 `page`。反馈的 `note` 是历史备注；draft 图片块 `note` 是说明。不能按 note 全局删。[S7]
9. **快速录入确实会加入 AI 标记。** `quick.js::recognize()` 合并 `data.labels`；`ai_assist.py` 的两个分类模板都要求 labels；`state.js::mergeClassification()` 还会直接改难度，不是所有字段都只补空。[S8]
10. **历史已有时间线和对错色条。** 缺的是可直接阅读的题目/变化摘要；当前详细内容主要是折叠后的 payload 文本。不是从零增加历史功能。[S9]
11. **缓存 token 已经贯通。** `openai_compat.py::_usage()` 读取 OpenAI/DeepSeek 缓存字段，`assistant/state.js` 按 round 累加 cached；检查器已有缓存命中绝对量，没有完整比例/总量表达。`ai_assist.py` 的辅助模型调用目前主要返回文本，不提供同等完整的用量归属。[S10]
12. **v1.35.0 已修复一批重要数据保护问题。** 正文 blob 覆盖、身份校验、入库及收件箱并发、助手迟到请求等是本次需要保护的基线，不能重复宣称这些全部仍未修复。[S11]

### 2.2 不变量

- 题库正文写入仍走现有 creation/content_history/Ledger 链路；草稿保存不等于入库。
- 只有实际练习反馈才增加练习次数、改变熟练度和排期。
- 不伪造用户错因，不把模型建议当成已确认事实。
- 分类、知识点、用户标记、熟练度状态是不同概念；R9 不等于删除全站标记能力。
- 保留草稿修订号、来源图片 SHA 引用、块顺序、人工框优先、独立训练任务以及按版本入库。
- 对话、草稿和练习卡有自己的生命周期；不得把聊天附件、草稿与正式题目的删除混成一个动作。
- 不更换前端框架，不修改 SM-2/熟练度算法，不启动新训练，不引入订阅、账号或云同步系统。

## 3. 最终预期行为

### 3.1 AI 草稿：首先给用户看即将入库的题目（R1）

桌面采用“待审队列 + 内容审核区 + 可收起来源对照”结构。队列紧凑显示科目、分类、题干摘要、状态和阻塞原因。审核区默认渲染题目及答案/解析，不默认铺满 textarea。知识点和错因在内容附近显示；修改时切换局部编辑，不打断整题的阅读位置。来源图对照可按需固定在旁边；屏幕不够宽时改为抽屉，不硬塞三栏。

手机一次呈现一题。顶部为“第 n/m 题”、队列入口和上一题/下一题；内容使用“题目 / 答案解析 / 信息”切换，原图通过独立预览打开。框选工具只在点击“调整框选”时进入。训练任务默认收起并标注不影响纯文本题审核，必要的入库阻塞则在首屏显示。

页脚保留现有可达操作，但调整主次：主按钮“保存并入库，下一题”；次按钮“暂存”；跳过、丢弃等进入清晰的次级入口，丢弃仍确认。已有内容需要很多阅读滚动时允许正常滚动；目标是消除来源图、训练信息、重复表单造成的无效滚动，而不是承诺任何长题都一屏放下。

保存并入库必须是受控串行流程：刷新当前草稿快照 → 保存脏字段并取得新 revision → 用该 revision 请求 commit → 只有成功才前进。保存失败、409、网络中断都不能进入下一题或提交旧内容。重复提交仍复用 commit_operations 的已有入库身份。

保持 textarea 选区、KaTeX、图片与滚动位置；列表刷新不能替换未保存的人工编辑。`done` 草稿正文保持只读；其独立训练任务不因此被删除或伪造完成。

### 3.2 快速录入：真正修复居中和空状态（R2）

将 `.crw-pane label` 收窄为明确的表单字段类，避免匹配上传区 label、checkbox label 或其他组件。上传组件保持由自身 CSS 管理布局，不用一串 `!important` 强压回去。

宽屏题图与答案图并排，窄屏纵向排列；两边同一中心轴。图标、主文案、说明分别居中。空缩略图容器不渲染；空状态信息不永久占一行。题图必选、答案可选保持清楚；答案区默认提供紧凑入口，展开/粘贴答案后呈完整区。识别与提取按钮放在有图时才有意义的位置，禁用态给出原因。

粘贴目标明确可见，点击题图/答案图切换目标；不能因布局优化丢失剪贴板、图序、删除附件或手机拍照选择能力。

### 3.3 题目字段识别与标记边界（R8、R9）

将识别拆成“产生候选字段”和“应用候选字段”。统一候选数据至少表达字段值、证据来源、源版本和是否待确认。科目、分类、知识点可补全；难度要区分默认 5、AI 值和人工值，不能把默认值与人工确认值混为一谈。

错因分为两类：

- 题图、原始转写或用户原话已经明确出现的错因，可提取为候选并展示来源。
- 仅依据题目推测的错因，标为“可能的错因”，不得自动作为事实写入。没有依据就留空，不能默认填写“粗心”“概念不清”。

现有 cause_statement 原话约束必须保留。若支持图片证据，新增受控的 image SHA + 可见文字/区域引用，并校验其属于当前题目来源；不得把模型自己的分析伪装成用户原话。无法验证时回到人工采纳。

AI 结果应用规则：空字段可补；已经人工修改的字段默认不覆盖；用户明确点击采纳才替换。请求同时绑定 item/draft id、source fingerprint、revision、字段脏状态。A 图识别结果到达时用户已切到 B 图，不得填进 B；识别期间手工更改过的字段也不得被覆盖。新建题卡、快速录入共享此规则；已入库题目的识别只生成预览补丁，确认后走正式历史写入链路。

**快速录入的 labels 永远不属于 AI 可应用字段。**

1. quick 分类调用不在提示词及 schema 中要求 labels。
2. 服务端 quick 分支对白名单外字段过滤/拒绝，即使模型返回 labels 也不透传为有效补丁。
3. 前端删除 `data.labels` 合并及“已生成标记”文案；重识别不得增、删、清空任何人工标记。
4. 手动标记选择、保存已有标记不受影响；助手中明确调用现有打标记工具也不因 R9 被全站关闭。
5. `classify_question` 是共享能力，允许字段应由受控调用方传入，不能简单全局删除 labels 导致别的入口行为无意改变。

### 3.4 删除笔记本页码（R6）

删除 quick 的输入/状态/payload、题卡 `page` 输入/状态、draft 新写入路径中相关字段、create_question 中页码参数及 Markdown 模板新输出、题目面板中的活动显示入口。扫描 CLI、API schema、导入、导出、模板、文档、测试，修改实际仍依赖页码的命中点。

旧版 API 请求带页码时，在明确的兼容适配处丢弃并返回 deprecated_fields 提示；不再写入活动题目元数据。不要静默把它变成“备注”。保存旧 draft/inbox 时应在迁移/归一化层移除该活动字段。

不重写过去的 Ledger commit 和正文 blobs，不在升级时批量重写所有旧题 Markdown。旧题原始文本中的页码可作为非活动遗留字段读入但不专门展示；以后正常编辑时按新格式保存。若需要把旧题实体文件中的每一行页码也彻底抹除，那是额外的一次性数据清理，须备份、预览和单独授权，不混入默认升级。

必须保留反馈 `note` / CSV `Note`、草稿图片说明 `note`、记录修正原因、正文 `# 备注`、来源图片编号和任何分页信息。

### 3.5 助手拖拽与站内图片预览（R3）

接收范围从输入框扩大到当前聊天主面板：拖进消息区或输入区均出现统一 drop overlay。仅接管实际文件拖拽，不拦截选中文字、网页链接或系统滚动。用 enter/leave 计数避免穿过子元素时遮罩闪烁；文件拖到当前聊天区域时阻止浏览器直接导航到文件。

本次默认修复已有图片附件能力，接收 PNG/JPEG/GIF；沿用现有最多 6 张、单张 8MB 等前后端校验与压缩流程。不把 accept="*" 当成支持任意文件。PDF/TXT/其他格式明确提示当前不支持；通用文档解析器不属于本次必做项。后续如另加格式须独立定义转换与安全契约。

待发送图片和历史图片统一进入拟新增 `ui/image-viewer` 组件：缩放、适应屏幕、图片间切换、下载、关闭；新标签打开降为次级操作。图片预览复用现有 dialog/overlay 焦点管理，支持 Esc、返回键、关闭后焦点恢复和背景滚动锁；来源图使用同一预览基础能力。

异步读取/压缩必须绑定发起时的 conversation generation。处理过程中切换聊天、清空附件或离开页面，迟到结果不加入新对话。已发送图按持久引用解析，预览不重新上传。释放临时 object URL；不把 base64 大串塞进路由、日志或聊天文字。

### 3.6 手机助手（R4）

手机聊天模式用一层紧凑导航表达会话标题、会话列表和更多菜单；外壳仍可离开助手，但不要把两个完整标题栏一直叠在顶部。消息区是主要滚动区；输入区在实际可视区域内，不依赖固定 rem 猜测浏览器/键盘高度。

优先用现有 flex/grid 与正确 min-height/min-width 解决结构；对键盘确实需要补偿的机型再使用 VisualViewport 的尺寸/偏移变化，并做节流、监听释放、缩放保护和回退。不能在用户缩放时误判成键盘而强制反向缩放。

输入空态为一行，移动端增长到约 4 行后内部滚动；长文本保留完整内容，并提供展开编辑入口。已有 `field-sizing` 继续渐进使用，不支持时用测量回退。中文输入法 composition 期间不得误触发送；手机 Enter 默认换行，点发送按钮发送；桌面保留 Enter 发送、Shift+Enter 换行。

快捷建议只在空对话或确有必要的空输入态出现，键盘弹出/输入中收起。统计收纳到小型用量入口；附件为可横向滚动的紧凑条。长用户粘贴消息提供“展开全文”，但不能丢失复制原文能力。工具参数、长运行轨迹默认收起，回答、待确认操作和练习/草稿卡优先展示。

保持已有会话切换迟到结果保护、长轮询重放、停止/插话、粘贴附图、滚动跟随与“跳至最新”。用户向上看历史时不要每个 token 都拉回底部。

### 3.7 AI 新能力（R5 的分类与草稿部分）

**分类：** 拟新增 `create_category` 工具，默认 confirm。AI 为当前草稿建议新分类可先留在草稿，用户入库时确认；独立创建永久分类才使用工具确认。这样既允许创建，也不在日常识别时不停要求用户确认空目录。

后端将 `creation.py` 已有的目录/锚点创建抽成公共领域函数（拟新增 `omrs/taxonomy.py`），并让建题调用同一函数。默认沿用现有分类目录与锚点作为持久表示，不再平行建立一套不可同步的分类数据库。`collect_taxonomy()` 和前端建议源补充安全识别的空分类目录/锚点，使创建后零题分类也可见；不通过创建假题维持分类。

subject + category 是身份边界；同名分类可属于不同科目。服务端规范化空白、校验路径和保留目录、禁止 ../ 与符号链接逃逸。创建幂等，已有锚点不覆盖，科目索引只补缺失链接。部分失败不得留下被当成成功的半成品。工具写入进入预算与明确活动记录；不因没有题目 commit 就显示“没有任何写入”，不宣称不支持的自动撤销。

**草稿：** 拟新增 `update_draft` 工具，自动写入未入库草稿，但保持待审核。工具参数为 draft_id、expected_revision、字段补丁和以稳定 block_id 定位的块操作。`get_draft` 增加编辑所需的 block_id、revision 和来源引用。只允许明确白名单字段；不允许写 uid、question_id、入库状态、训练验收结果或任意图片路径。

服务端复用现有 update 校验、全局写锁内短事务及 revision 比较。done/discarded、入库中、未知块 ID、无权引用的图片、旧 revision 都拒绝。只改指定块，不重建整份 blocks 导致裁图框/顺序/人工来源丢失。草稿编辑活动记录最少保存操作者、run/call、旧新 revision 和实际字段变化；不能把草稿修改误记成正式题目 Ledger 内容修改。

人正在编辑同一草稿时，聊天卡显示“已有新版本”，不热替换本地输入。重新读取并展示差异后合并；禁止模型拿到 409 后不读新版本直接改用新 revision 重试。若字段已被人工确认保护，AI 修改先出建议或明确确认，不静默覆写。编辑成功刷新草稿列表/计数/聊天卡；应扩展已有变更通知，而不是只等 Ledger commit 才刷新。

### 3.8 聊天练习卡：不是正式 Session（R5 的临时练习部分）

用户看到一张卡：“离子方程式巩固 · 8 题 / 开始练习”。点击直接进入即时练习，载入生成卡片时的明确题序，而不是再次按推荐重新随机选题。界面名使用“临时练习”或“练习卡”；内部用 PracticeCard，避免与正式 Session 类型混用。

拟新增 `create_practice_card` 工具。推荐结构：

```json
{
  "kind": "practice_card",
  "schema_version": 1,
  "card_id": "PC-<服务端生成标识>",
  "title": "离子方程式巩固",
  "items": [
    {"question_id": "<稳定题目身份>", "uid_at_creation": "<当时UID>", "source": "due"}
  ]
}
```

conversation/run/call 的归属由服务器提供，不接受模型任意指定。卡片作为结构化工具结果/聊天消息元数据持久化在现有 agent.db，不写 sessions.csv，不产生 session.create，不占用正式调度的活动题目集合，不计入正式待完成调度。使用 tool_calls/messages 的完整结构作为真源，不从展示摘要或可能被截断的展示文本反解析卡片。卡片结构与运行事件重放有版本号，旧消息仍可打开。

前端通过拟新增受控解析入口与路由 handoff，把 card_id 交给 instant。`instant/index.js` 增加“按显式列表加载”路径；沿用题面、答案展开、判对错、打分与提交，不复制整套页面。拟定路由形态 `#/instant?practice=<card_id>` 须先核对 router 查询解析能力，必要时补齐解析，不能把整个 JSON 塞 URL。目标面板未挂载时仍能保留 handoff，避免一次性 bus 事件提前发出而丢失。

启动只验证题目仍有效并解析稳定 question_id；题目移动后用新 UID，删除/停用则说明并跳过，不悄悄补入别的题。卡片本身不包含答案。未入库草稿不直接当正式题目加入；要练习先入库。

默认一张卡对应一个可继续的练习 attempt；刷新后可恢复。题序/进度仍只作为聊天关联元数据存于 agent.db，不建立正式 Session。重新练一轮显式创建新 attempt id；不能仅靠秒级时间戳区分并发。

只有用户实际提交才调用反馈链路并记 IMM-* 来源。必须补齐服务端幂等：使用 attempt_id + question_id/条目 ID，网络成功但响应丢失、刷新重发和双击不应增加两次 Attempts。幂等凭据与 review.batch_submit 的实际提交必须形成可恢复的一致边界，不能分别写两个数据库后假定永不崩溃。优先把稳定 request/entry 标识存入 Ledger feedback payload，并在写锁下检测已有提交；可重建索引，不把另一个临时数据库当唯一防重依据。

当前 instant 的提交成功分支按发送的 rows 锁定题目，而 backend 可以逐条返回 error；因此新链路必须按逐题 results 只锁定成功项，失败项可修正重试。以返回的有效结果更新卡片进度，而不是把 HTTP 200 等同于整批成功。

删除对话后不能再新启动其卡片；已真实提交的历史不随聊天删除。进行中的练习可保留当前页面只读快照并提示关联会话已删除，提交行为按已签发 attempt 与服务端规则处理；不再依赖被删除消息获取对错。若未签发有效 attempt，禁止提交伪造卡片。

### 3.9 历史记录：首屏回答“我做了什么”（R7）

保留时间线与修正模式，但默认摘要顺序改为：动作中文名 → 题目/题组摘要 → 对错/主观分或实际字段变化 → 时间与来源；commit_id、seq、技术 commit_type 收入详情。

练习批次显示题数、对错数、科目分布和部分题目摘要，展开查看逐题结果；内容更新显示改了题目/答案/错因哪一节及简短前后差异；移动显示分类前后；撤销/恢复仍按完整 retraction_state 判断。正文、来源或字段不足时显示“无可用历史摘要”，不编造旧数据。

“当前题目摘要”与“当时的内容”须明确区分。旧事件未记录熟练度前后值时，不拿今天的熟练度冒充当时值；有可验证快照才显示该差值。新反馈可增加受控摘要字段，旧 Ledger 不回写。正常卡片先提供确实存在的对错/分数，不能为了做漂亮卡片每次对每条历史重新跑全库回放。

分页/分批加载摘要，详情和历史正文按需取，避免每张卡 N+1 读取题目与 blobs。筛选/分页后撤销状态仍从完整链或服务端快照求得，不能仅用当前页做撤销判断。失败保留旧列表，维护展开状态与滚动锚点。纯草稿保存和练习卡创建不是 Ledger 事件，不伪造塞进题目历史；在聊天活动中表达。

### 3.10 下拉与折叠组件（R10）

现有 ui/select.js 本来就是样式化的原生 select，因此只改 control CSS 无法保证系统弹出层与网页统一。对科目/分类/知识点等需要搜索、空分类、新建入口的控件，拟新增共享 combobox；手机选择列表用抽屉/底部面板，桌面用菜单浮层。对简单二元/少量选项可使用已有 segmented 或 menu。系统文件选择器、系统确认框等不做伪网页重写。

折叠区统一 summary 的间距、箭头、hover、focus、expanded 状态与内容边界，可保留 details/summary 原生语义，不必为了换三角形重写完整状态机。分类候选按科目过滤；不再使用所有科目分类混排的全局 datalist。

键盘要求：上下键导航、Enter 选中、Esc 关闭、Tab 正常离开；中文输入组合不误选择。浮层不被 overflow:hidden 裁掉，不脱离触发元素，不被其他 modal 抢焦点。深浅色、200% 缩放、360px 手机、长中文项、无候选/加载/出错/禁用态均可用。不要把“完全自定义”做成失去键盘能力的 div 列表。

### 3.11 缓存比例与本次总用量（R11）

圆环支持“上下文 / 缓存”指标切换，保留用户上次选择；指标名称和分母明确显示，手机收纳长数字到弹层。上下文占用表示最近请求的上下文，缓存率默认表示本次主对话运行已获得有效统计的输入命中情况，二者不能共用一个分母。运行详情独立展示主对话、图片转述/看图辅助调用及已知总量。

统一用量契约建议为 input_total、output_total、cache_read、reasoning_output、known/source/scope、request_id/round_id；未知用 null，不用 0。主对话沿用现有 usage 字段向后兼容，由公共归一化层产生新字段；不要求新增另一个完整 provider 框架。

公式：

- 单个范围的总 token = 各请求 input_total 之和 + 各请求 output_total 之和。
- 缓存命中率 = 有缓存统计的请求 cache_read 之和 / 同组请求 input_total 之和。
- 有些请求无缓存字段时，不将它们当作未命中；标为“部分调用可统计”，附覆盖范围，不展示看似完整的百分比。
- 对现有 OpenAI 兼容口径，cached 已属于输入，reasoning 已属于输出，不再次加进总量。缓存占比也不等于费用节省比例。

`openai_compat.py` 继续兼容 prompt_tokens_details.cached_tokens 与 DeepSeek prompt_cache_hit_tokens；显式 0 与缺字段必须区分，不能简单用 or 连续回退。若供应商只给 hit/miss，可在已验证该协议时求和得到输入。负值、cached 大于 input、字段类型错误须标记异常，不静默做漂亮百分比。

`assistant/state.js` 改为按稳定请求标识归约；流式中显示估算，结束时以服务端 usage 替换同一轮估算，completion=0 也属于有效结果。终止/断网缺最后 usage 时显示估算或部分统计。重连、重复事件、刷新重放不得重复累计。

辅助调用目前可能丢弃 usage，因此要在 ai_assist 的模型调用包装中增加可选用量采集与 run/call 归属，不改变只需要文本的旧调用者行为。使用本地转述缓存时没有新 API 调用，不能把本地缓存命中当成模型 prompt cache。独立草稿后台 job 属于另一任务，单列并明确排除；已经归入主 run 的子请求不得重复累计。

示例验收：两轮输入 1000、9000，缓存 0、9000，输出共 500；本次主对话总量为 10500，缓存率 90%，不是两轮百分比平均后的 50%。若第二轮未返回缓存字段，则不能报告完整的 0% 或 90%。

每阶段是风险控制与提交边界，不是提前结束交付的理由。最终到 R1–R11 全部通过并形成 v2.0.0 候选发布才结束实现；生产部署另授权。

| 阶段 | 核心任务 | 依赖 | 主要提交切片 | 放行条件 |
|---|---|---|---|---|
| P0 | 基线、契约、夹具、复现记录 | 无 | 计划/基线；契约测试 | 11 项均有对应入口和验收，不覆盖已有工作 |
| P1 | AI 草稿审核工作台 | P0 | 审核布局；编辑与保存入库 | 手机逐题审核、409/失败不丢编辑、训练不被破坏 |
| P2 | 快速录入、字段识别、禁改标记、页码退役、共享选择器 | P0；复用 P1 必要组件 | CSS与控件；识别补丁；页码兼容 | 居中、人工优先、标签不变、旧数据可读 |
| P3 | 助手拖拽、预览、手机交互 | P0；复用共享浮层 | 附件；预览；键盘与布局 | 主消息区可拖、预览不离页、输入法/键盘真机通过 |

## 5. 关键技术决策汇总

| 问题 | 默认决策 |
|---|---|
| 是否换 React/Vue 或构建系统 | 不换，保留 assets/app 原生模块及现有 morph/路由 |
| 草稿是否自动入库 | 不。AI 可修订待审草稿，正式写入仍审核 |
| 是否删除训练能力 | 不。降低默认界面权重，保留来源与标注不变量 |
| 快速录入是否保留 AI 标签开关 | 不增加开关；此入口禁止 AI 改标签，手动能力保留 |
| 无依据错因如何处理 | 留空或待采纳建议，不自动落成事实 |
| 空分类如何存储 | 提取现有目录/锚点实现，统一词表读取；不引入平行数据库 |
| 独立新分类是否确认 | 默认确认；草稿中的分类建议随入库审核 |
| 临时练习是否写 sessions.csv | 不写，卡片和进度归属聊天，真实反馈仍进 Ledger |
| 是否新增一套练习 UI | 不新增，扩展现有 instant 的显式题序加载 |
| 是否把所有旧页码物理抹除 | 不在默认升级破坏旧正文/历史；活动功能和新写入彻底移除 |
| 拖拽是否等于任意文档解析 | 否，本次明确支持现有图片范围；其他格式清楚报错 |
| token 缺失是否显示 0 | 不，区分实测、估算、部分与未知 |
| 版本号与存储 schema 是否同一件事 | 不，应用升级 v2.0.0；存储迁移独立版本、幂等执行 |

## 6. 边界情况与风险登记

| 情况 | 必须行为 |
|---|---|
| 人工草稿脏数据遇到 AI 更新 | 保留本地输入，提示新版本并展示冲突，不热替换 |
| AI 修改草稿碰到 done/discarded/入库中 | 拒绝；不反向恢复成 review |
| 同一来源图被多个草稿使用 | 保留 SHA 引用及人工框优先，不合并成错误训练真值 |
| 保存成功、commit 响应丢失 | 重试复用同一入库操作，不另建 UID |
| 待发送图片读取时切换会话 | 丢弃旧 generation 的写回，不附到新会话 |
| 拖入 URL、文字或不支持文件 | 不误判图片；不触发非预期导航或悄悄消失 |
| 软键盘、横竖屏、浏览器地址栏变化 | 输入仍可见、可关键盘，消息区不出现永久空白 |
| 中文候选词确认 | 不触发发送/选项提交 |
| 分类重名/非法路径/锚点已存在 | 幂等或明确拒绝，不覆盖既有文件 |
| 练习卡部分题目删除或停用 | 说明不可用项，保留其余原顺序，不静默换题 |
| 练习提交部分成功 | 仅成功项锁定；失败项保留并可重试 |
| 练习提交落账后进度写回失败 | 以 Ledger 稳定提交身份恢复，不重复反馈 |
| 聊天删除 | 禁止重新开启卡片；真实练习历史不删除 |
| 使用旧对话/旧 usage 事件 | 不崩溃，不能确定的缓存字段显示未知/历史不完整 |
| 只返回部分调用的 usage | 显示已知总量与统计范围，不伪称全量 |
| 历史分页后的撤销链 | 仍使用全链状态，不能因目标不在当前页而错误恢复 |
| 升级遇到旧页码 | 活动读写忽略，保留历史证据；备注不受影响 |
| 版本升级后回退 | 代码可回退不等于数据可降级；有 schema 不兼容则使用备份或明确的降级方案 |

## 8. 验收标准

### 8.1 用户操作验收

- 草稿首屏可以看到当前题干内容或明确阻塞原因；不必先滑过训练与原始大图。
- 手机完成“查看题目 → 查看答案 → 必要修改 → 入库 → 下一题”时，不需要为寻找操作按钮来回滚长页面。
- 框选已正常的草稿不强迫再次进入框选；训练未完成不误阻断满足入库条件的纯文本草稿。
- quick 空状态图标和文案中心轴一致；答案可选；paste target 清晰。
- 手工标记集合在任何 quick AI 调用前后逐项相同，包括模型返回异常 labels 和清空数组时。
- 题图中明确写有错因时有来源可核对；没有错因时不自动写“粗心”。
- AI 调用过程中用户改过的难度、分类、错因不会被迟到响应覆盖。
- 待发送图和历史图点击均站内预览，关闭后回原位置；消息区可拖图。
- 360/390/430 宽手机与 768/1024/1440 宽视图无页面级横向溢出；长公式允许题面局部滚动。
- 手机真实软键盘开启、候选词确认、发送、关键盘、横竖屏切换都正常；不能只用缩小桌面视口验收。
- 草稿编辑工具处理旧 revision 返回冲突，原内容和人工框不损失；入库后拒绝改草稿正文。
- 新建零题分类在分类候选中可见，重复请求不重复创建，跨科目同名不串用。
- 聊天卡开始练习保持题序，sessions.csv 和正式 Session 数不变化；创建卡片与打开卡片不增加 Attempts。
- 实际练习提交后存在真实反馈；双击、刷新重发、响应丢失重试均只增加一次 Attempts。
- 一批 3 题中 1 题服务端报错时，只锁定 2 题成功项。
- 新题 Markdown 不再输出 `页码:`；quick/题卡无页码入口；反馈备注和图片说明照常保留。
- 历史默认显示题目/动作/结果而非只有技术 ID；分页与筛选不破坏撤销/恢复。
- 两轮 1000/9000 输入、0/9000 缓存、500 输出示例得到 90% 与 10500；重放结果一致。
- 无缓存字段显示“未知/未返回”；明确 0 显示 0%；没有最终 usage 的中断显示部分/估算。
- 辅助调用有单独归属；只在有完整统计时标“本次总量”，否则标“已知总量”。

### 8.2 量化与对比

在 P0 固定同一组纯文本、图文混排、长答案、框选待确认、缺错因、共享来源图、多轮 AI 的夹具。记录改前改后的完成时间、寻找控件的滚动次数、点击数、首屏内容、页面横向溢出和错误。不同任务难度分组比较，不混用一张短题和另一张长题宣称速度提升。

拟定最低 UI 条件：360px 宽可操作，触摸主按钮目标至少 44×44 CSS px；200% 缩放不丢动作；默认空输入不占多行；关键确认不只依赖颜色。不要通过缩小正文文字达成所谓高信息密度。
